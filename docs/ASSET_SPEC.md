# MuseDungeon 画像アセット仕様

[DESIGN.md](DESIGN.md) §9 の補足。2D レンダラーが要求する画像アセットの**技術仕様**を定める。
画風・配色・個々のデザインは本書では決めない。本書の目的は、後から画像を別途制作し、コードを変えずに差し込めるようにすることである。

末尾の §10 に「実装担当の判断に委ねる点」をまとめた。

---

## 1. 基本方針

1. **画像が 1 枚も無くてもゲームは動く。** 既定テーマ `glyph`（色付きタイル＋文字）が全アセットの代替になる。画像テーマは未提供のアセットを `glyph` 表示にフォールバックする。よってアセットは少しずつ追加できる。
2. **ゲーム側は見た目を知らない。** サーバーが送るのはコンテンツ ID と状態だけ。ID から画像への対応は、クライアント側の**テーマ**（画像一式＋マニフェスト）が持つ。
3. **最小要件は「1 種別につき静止画 1 枚」。** 向き・アニメーション・バリエーションはすべて任意の上乗せで、無い場合はレンダラーが手続き的な演出（移動の補間、被弾時の点滅など）で補う。
4. **見た目用の状態はクライアントだけが持つ。** 向きやアニメーションの進行は World State に含めず、イベントから導出する。

## 2. グリッドと視点

| 項目 | 仕様 |
|---|---|
| グリッド | 正方形の直交グリッド。1 セル = 1 タイル。アイソメトリック（斜め格子）は対象外 |
| セルサイズ | テーマがマニフェストで宣言する `cellSize`（px、正方形）。**標準は 32×32**。16／24／48／64 も可。1 テーマ内では全アセットが同じ `cellSize` に従う |
| 視点 | 真上、または正面寄りの見下ろし。どちらを採るかは画風の決定事項だが、**1 テーマ内で統一**する |
| 壁 | 壁は 1 セルを占める地形で、セル全体を覆う 1 タイルとして描く。壁の「高さ」のために別セルを使う表現（壁の上面と側面を別セルに分ける方式）は使わない |
| 画面座標 | 左上原点、x は右（東）、y は下（南）。ゲーム座標と一致 |
| 拡大縮小 | レンダラーが表示倍率を決める。補間方法はテーマが `scaling: "nearest" | "linear"` で宣言する |

### 2.1 セルからはみ出すスプライト

- ゲーム上、すべてのエンティティは 1 セルを占有する（MVP に複数セルを占める存在は無い）。
- 見た目としては、フレームをセルより大きくできる。上限は幅 2 セル・高さ 2 セル。
- 基準点（アンカー）は既定で**フレーム下端の中央**で、これをセル下端の中央に合わせる。アセットごとに `anchor` で上書きできる。
- はみ出しは主に上方向を想定する。重なりは行（y）の小さい順に描くことで解決する（§4）。

## 3. 画像ファイル形式

| 項目 | 仕様 |
|---|---|
| 形式 | PNG、32bit RGBA、sRGB、非乗算（ストレート）アルファ |
| 透過 | 下表のとおり |
| 余白 | フレームの外周に余白や枠線を入れない。フレームは隙間なく並べる |
| 影 | レンダラーは影を描かない。必要ならスプライト内に半透明で含める（フレーム内に収めること） |
| 視界表現 | 「記憶しているが今は見えない」セルの暗転と、未知セルの塗りつぶしはレンダラーが行う。**暗い版・記憶版の画像は不要** |

**透過の要否:**

| 分類 | 透過 |
|---|---|
| 地面系の地形（床・壁・水など、セル全体を覆うもの） | **不透明**。セル全体を塗る |
| 地面の上に載る地形（扉・階段など） | **透過あり**。下にそのバイオームの床が描かれる |
| 地物・アイテム・キャラクター・モンスター・エフェクト・アイコン | **透過あり** |

地面系のタイルは、同じ種別同士（バリエーション含む）で上下左右に並べて継ぎ目が出ないこと。

### 3.1 シートの並べ方

1 アセットの 1 アニメーションにつき 1 つの PNG とする。静止画しかないアセットは PNG 1 枚でよい。

```
          frame0  frame1  frame2 ...   → 横方向 = フレーム（時間順）
row 0:    [ ]     [ ]     [ ]          ↓ 縦方向 = 向き
row 1:    [ ]     [ ]     [ ]
```

- 全フレームは同じサイズ（`frame.w × frame.h`）。
- 行の意味は向きの数で決まる（§5）。向きが 1 つなら 1 行。
- 配布時に 1 枚のアトラスへ結合するかどうかは実装の判断で、制作者は気にしなくてよい。

## 4. レイヤー構造

下から上の順に描く。制作するアセットが属するのは L1〜L5 と、L7 のアイコン類のみ。

| # | レイヤー | 内容 | 画像の出どころ |
|---|---|---|---|
| L0 | 背景 | 未知領域の塗り | レンダラー（テーマの色指定のみ） |
| L1 | 地面 | 床・壁・水など、セルを覆う地形 | **アセット**（不透明） |
| L2 | 地形オブジェクト | 扉・階段など、床の上に載る地形 | **アセット**（透過） |
| L3 | 地物・アイテム | 泉・祭壇・発見済みの罠、床に落ちているアイテム。同一セルでは地物の上にアイテム | **アセット**（透過） |
| L4 | アクター | プレイヤー・モンスター。行（y）の小さい順に描く | **アセット**（透過） |
| L5 | エフェクト | 命中・回復・飛び道具など | **アセット**（透過。無ければ手続き的演出） |
| L6 | 視界 | 記憶セルの暗転、未知セルの遮蔽 | レンダラー |
| L7 | オーバーレイ | HP バー、状態異常アイコン、接辞バッジ、プレイヤー識別マーカー、カーソル、経路表示、ダメージ数字、吹き出し | レンダラー＋**アイコン類のアセット**（任意） |

- 同一セルにアイテムが複数ある場合は、最上位の 1 つ＋「複数あり」の印（レンダラー描画）とする。
- 装備の見た目への反映（着せ替え）は MVP では行わない。キャラクターの画像はクラスごとに 1 種類。

## 5. 向き

World State にエンティティの「向き」は無い。向きはクライアントが直近の移動・攻撃イベントの方向から導出する、見た目専用の状態である。

| `facings` | 必要な行 | 用途 |
|---|---|---|
| `1`（既定・**必須はこれだけ**） | 1 行。向きの区別なし | すべてのアセット |
| `2` | 1 行。**東向き（右向き）**で描く。西向きはレンダラーが左右反転する | アクター（任意） |
| `4` | 4 行。上から **南（手前）・西・東・北（奥）** | アクター（任意） |

- ゲームの移動は 8 方向だが、8 方向の画像は要求しない。斜めは左右成分で東西に寄せる（北東・南東 → 東、北西・南西 → 西）。
- 向きを持てるのはアクター（プレイヤー・モンスター）のみ。地形・地物・アイテムは常に `1`。
- 飛び道具のエフェクトだけは別扱いで、`orient: "rotate"`（東向きで描いた 1 枚をレンダラーが進行方向へ回転）か `orient: "none"`（回転しない）を選ぶ。

## 6. アニメーション

### 6.1 共通規約

- アニメーションは「名前付きのフレーム列」。マニフェストで `frames`（枚数）、`frameMs`（1 枚の表示時間、既定 150）、`loop`（繰り返すか）を宣言する。
- 定義されていないアニメーションは、下表のフォールバックに従う。**どのアセットも `idle` の 1 フレームがあれば成立する。**
- リプレイの再生速度に応じて、レンダラーがアニメーションを早送り・省略する。アニメーションの長さがゲーム進行を待たせることはない。

### 6.2 アクター（プレイヤー・モンスター）

| 名前 | 必須 | 推奨フレーム数 | ループ | 再生の契機 | 画像が無い場合の代替 |
|---|---|---|---|---|---|
| `idle` | **必須** | 1（動かすなら 2〜4） | する | 常時 | – |
| `move` | 任意 | 2〜4 | する（移動中のみ） | `entity_moved` | `idle` のままセル間を補間移動 |
| `attack` | 任意 | 2〜4 | しない | `attack` | `idle` のまま対象方向へ小さく突き出す |
| `hurt` | 任意 | 1〜2 | しない | `damaged` | `idle` を一瞬点滅させる |
| `die` | 任意 | 3〜6 | しない | `died` | `idle` をフェードアウト |
| `sleep` | 任意 | 1〜2 | する | AI 状態が睡眠 | `idle` ＋状態アイコン |

### 6.3 地形・地物・アイテム

| 分類 | 仕様 |
|---|---|
| 地形 | 既定は静止画 1 枚。任意で `idle` ループ（水面など、2〜4 フレーム）。全セル同期で再生する |
| 扉 | 「閉じた扉」「開いた扉」は別々の地形 ID で、それぞれ静止画。開閉の中間アニメーションは不要 |
| 地物 | `idle`（1 フレーム〜）。状態を持つ地物は状態名ごとに 1 枚（例: 使用済みの泉 → `used`）。状態名は content の `features` 定義に従う |
| アイテム | 静止画 1 枚。アニメーションなし |

### 6.4 エフェクト

すべて任意。無い場合はレンダラーの手続き的演出、または演出なしになる。

| 種類 | 形 | 推奨フレーム数 |
|---|---|---|
| その場で再生（命中・クリティカル・空振り・回復・毒・レベルアップ・瞬間移動・状態異常の付与） | 対象セルを基準に 1 回再生 | 3〜6 |
| 飛び道具（投擲・遠隔攻撃） | 発射元から対象へ移動する 1〜2 フレーム | 1〜2 |

投げたアイテムは、専用のエフェクトが無ければそのアイテム自身の画像を飛ばす。

## 7. アセット分類と ID

### 7.1 分類と対応するゲーム内データ

| 分類（`class`） | アセットキー | 対応するゲーム内データ | レイヤー |
|---|---|---|---|
| `terrain` | 地形 ID（例 `core:wall`） | content `terrain` の ID。Floor.terrain の各セル | L1／L2 |
| `actor` | モンスター種別 ID（例 `core:goblin`）、クラス ID（例 `core:warrior`） | content `monsters`／`classes` の ID。Entity.kind | L4 |
| `item` | アイテム種別 ID（例 `core:short_sword`） | content `items` の ID。Entity.kind | L3 |
| `appearance` | 外見 ID（例 `core:potion_look_03`） | 未鑑定アイテムの外見（§7.4） | L3 |
| `feature` | 地物 ID（例 `core:fountain`）、罠 ID | content `features` の ID。Entity.kind | L3 |
| `fx` | エフェクト ID（例 `fx:hit`） | クライアントがイベント種別から選ぶ（§7.5） | L5 |
| `status` | 状態異常 ID（例 `core:poison`） | content `statuses` の ID | L7 |
| `affix` | 接辞 ID（例 `core:swift`） | content `affixes` の ID | L7 |
| `ui` | UI 部品 ID（例 `ui:cursor`） | クライアント固定の一覧 | L7 |

**原則: アセットキーはコンテンツ ID そのもの。** 敵を 1 種類追加したら、同じ ID のアセットを 1 つテーマに足せば表示される。別途の対応表は要らない。

### 7.2 テーママニフェスト

テーマは 1 ディレクトリ＝ 1 テーマ。`theme.json` がすべての対応を持つ。ファイルパスは自由（ID に含まれる `:` はファイル名に使えないため、キーとパスは別物として扱う）。

```jsonc
// client/themes/<themeId>/theme.json
{
  "id": "example",
  "formatVersion": 1,
  "cellSize": 32,
  "scaling": "nearest",
  "background": "#000000",
  "fallbackTheme": "glyph",
  "assets": {
    "terrain": {
      "core:floor":                 { "file": "terrain/floor.png", "variants": 3 },
      "core:floor@core:damp_caves": { "file": "terrain/caves_floor.png", "variants": 2 },
      "core:wall":                  { "file": "terrain/wall.png", "autotile": "mask16" },
      "core:water":                 { "file": "terrain/water.png",
                                      "anim": { "idle": { "frames": 4, "frameMs": 250, "loop": true } } },
      "core:door_closed":           { "file": "terrain/door_closed.png", "layer": "object" }
    },
    "actor": {
      "core:goblin": {
        "frame": { "w": 32, "h": 32 }, "facings": 2,
        "anim": {
          "idle":   { "file": "actors/goblin/idle.png",   "frames": 2, "frameMs": 400, "loop": true },
          "attack": { "file": "actors/goblin/attack.png", "frames": 3, "frameMs": 80,  "loop": false }
        }
      },
      "core:warrior": { "file": "actors/warrior.png" }
    },
    "item":       { "core:short_sword": { "file": "items/short_sword.png" } },
    "appearance": { "core:potion_look_03": { "file": "items/potion_03.png" } },
    "feature":    { "core:fountain": { "file": "features/fountain.png",
                                       "states": { "used": { "file": "features/fountain_used.png" } } } },
    "fx":         { "fx:hit": { "file": "fx/hit.png", "anim": { "play": { "frames": 4, "frameMs": 50, "loop": false } } },
                    "fx:projectile": { "file": "fx/arrow.png", "orient": "rotate" } },
    "status":     { "core:poison": { "file": "icons/poison.png" } },
    "affix":      { "core:swift":  { "file": "icons/affix_swift.png" } },
    "ui":         { "ui:cursor":   { "file": "ui/cursor.png" } }
  },
  "categoryFallbacks": {
    "actor":       { "file": "fallback/monster.png" },
    "item:potion": { "file": "fallback/potion.png" },
    "item":        { "file": "fallback/item.png" }
  }
}
```

省略時の既定値: `frame` = `cellSize` の正方形、`facings` = 1、`anchor` = 下端中央、アニメーションなし（静止画）、地形の `layer` = content の地形定義に従う。

### 7.3 解決順

あるエンティティ／セルを描くとき、レンダラーは次の順で探し、最初に見つかったものを使う。

1. **完全一致**: 分類＋ ID（地形のみ、先に `地形ID@バイオームID` を試し、無ければ `地形ID`）
2. **カテゴリ代替**: `categoryFallbacks`。content の `category`（例 `potion`）を使い、`item:potion` → `item` の順
3. **代替テーマ**: `fallbackTheme`（通常は `glyph`）の同じ ID
4. **組み込みの「不明」表示**

カテゴリ代替のために、クライアントは起動時にサーバーから**公開カタログ**（各コンテンツ ID の分類・カテゴリ・表示名のみ。能力値や出現条件は含まない）を取得する。

### 7.4 未鑑定アイテム（情報隠蔽との関係）

未鑑定の薬・巻物を「本当の種別」の画像で描くと、正体が画面から漏れる。そのため:

- 未鑑定アイテムは、プレイヤー向けデータでは種別 ID が伏せられ、代わりに**外見 ID**（`appearanceId`）を持つ。レンダラーは `appearance` 分類でこれを引く。
- 外見の一覧（ID と表示名）は content 側で定義する。AI に渡る表示名（例として「赤い薬」のような文言）と、人間が見る画像は同じ外見 ID に紐づくので、**外見の画像はその表示名と矛盾しないように制作する**必要がある。表示名の内容自体はコンテンツ制作時に決める。
- 外見は、未鑑定になり得る種別の数以上を、カテゴリ（薬・巻物）ごとに用意する。
- 鑑定済みになったアイテムは種別 ID で `item` を引く。そこに画像が無ければ、引き続き外見の画像を使う（＝外見の画像だけ作れば足りる）。

### 7.5 個体差の表現（組み合わせごとの画像は作らない）

| 個体差 | 表現方法 |
|---|---|
| 接辞付き・深層強化されたモンスター | 元の種別の画像＋ `affix` のバッジ（L7）。バッジ画像が無ければレンダラーが色付きの印を描く |
| 接辞付きアイテム | 元の種別の画像のまま。区別は名前表示で行う |
| 複数のプレイヤー | クラスごとの画像＋レンダラーが描く識別マーカー（色付きの輪と名前）。プレイヤーごとの色違い画像は不要 |
| 敵対・中立・味方の区別 | レンダラーのマーカー |
| HP の状態 | レンダラーの HP バー（モンスターは 4 段階表示） |

### 7.6 エフェクト ID と UI ID（クライアント固定）

イベントからエフェクトへの対応はクライアントが持つ。MVP の一覧:

| ID | 契機 |
|---|---|
| `fx:hit` / `fx:crit` / `fx:miss` | `attack` の結果 |
| `fx:heal` | `healed` |
| `fx:status`（状態異常ごとに `fx:status@状態ID` で上書き可） | `status_applied` |
| `fx:levelup` | `level_up` |
| `fx:teleport` | `entity_moved` の mode が teleport |
| `fx:projectile`（アイテムごとに `fx:projectile@アイテムID` で上書き可） | `item_thrown` など |
| `fx:trap` | `trap_triggered` |

UI 部品（すべて任意）: `ui:cursor`、`ui:target`、`ui:path`、`ui:stack`（アイテム複数の印）。アイコン類（`status`・`affix`・`ui`）の標準サイズは `cellSize` の半分の正方形とする。

## 8. 地形の追加仕様

### 8.1 バリエーション

`variants: N` を指定すると、PNG に N 枚を横に並べ、セルごとに 1 枚を選ぶ。選択は座標から決まる見た目専用のハッシュで行い（ゲームの乱数は使わない）、同じセルは常に同じ絵になる。アニメーションと併用する場合は、縦方向をバリエーション、横方向をフレームとする。

### 8.2 オートタイル（任意）

壁や水の縁を隣接関係に応じて描き分けたい場合のみ使う。MVP では不要で、指定しなければ 1 枚の絵を全セルに使う。

- `autotile: "mask16"`: 上下左右 4 方向の隣が「同じグループ」かどうかの 4 ビットで 16 枚を引く。
- ビット: 北 = 1、東 = 2、南 = 4、西 = 8（同じグループなら立てる）。PNG には index 0〜15 の順に横 16 枚を並べる。
- 未知のセルは「同じグループ」として扱う（探索が進むたびに壁の絵が変わるのを抑えるため）。

### 8.3 バイオームによる差し替え

同じ地形 ID でも、バイオームごとに別の絵を使える（`地形ID@バイオームID`）。無ければ共通の絵を使う。したがって最小構成は「共通の床と壁を 1 組」で、バイオームごとの絵は後から足せる。

## 9. 制作対象の規模（MVP）

個々のデザインは未定。ここでは**枠の数**だけを示す。正確な ID の一覧は、コンテンツ定義から自動生成する（下記のチェックリスト）。

| 分類 | 最小（静止画 1 枚ずつ） | 備考 |
|---|---|---|
| 地形 | 6〜10 | 床・壁・閉じた扉・開いた扉・下り階段・上り階段＋バイオーム固有の地形。バイオーム別の床と壁（3 バイオーム）は任意 |
| プレイヤー | 2 | クラスごと |
| モンスター | 8 | |
| 装備・投擲アイテム | 9 | 武器 4・防具 3・投擲 2 |
| 外見（未鑑定の薬・巻物） | 7 以上 | 薬 4 以上・巻物 3 以上 |
| 地物 | 3〜5 | 泉・祭壇・罠など。状態違いは別途 |
| 状態異常アイコン | 4 | 任意 |
| 接辞バッジ | 6 | 任意 |
| エフェクト | 約 9 | 任意 |
| UI 部品 | 4 | 任意 |

必須なのは上から 6 分類の約 **35〜41 枚**。それも無ければ `glyph` 表示になるだけで、動作は妨げない。

### 9.1 チェックリストと検証ツール

制作と実装を切り離すため、`tools` に次を用意する。

- `assets:checklist`: 現在のコンテンツ定義から、必要なアセットキーの一覧（分類・ID・表示名・必須／任意）を出力する。制作の発注表になる。
- `assets:check <theme>`: テーマを検証する。未提供の ID、マニフェストにあるが content に無い ID、PNG の寸法が `frame × frames × facings` と合わないもの、不透明であるべき地面タイルの透過、を報告する。

## 10. 実装担当の判断に委ねる点

- PNG を実行時に個別に読むか、ビルド時にアトラスへ結合するか（結合する場合の縁の処理を含む）。
- 手続き的な代替演出の具体値（補間時間、点滅の色、フェード時間）と、高速リプレイ時にどの演出を省くか。
- `glyph` テーマの文字・色の割り当て。
- `mask16` より細かいオートタイル（角を含む方式）を追加するかどうか。追加する場合は `autotile` の新しい値として足し、既存の値の意味は変えない。
- 公開カタログの取得経路と、テーマの切り替え UI。
- マニフェストの細部（キー名など）。変更する場合は本書を更新し、`formatVersion` で互換性を管理する。

## 11. 本書で決めていないこと（アセット制作側で決める）

- 画風、配色、ピクセルアートか否か、真上か見下ろしかの選択、線や陰影の扱い。
- 個々の地形・キャラクター・モンスター・アイテムのデザイン。
- `cellSize` を標準の 32 以外にするかどうか。
- どこまで任意要素（向き、アニメーション、バリエーション、オートタイル、エフェクト）を作るか。
