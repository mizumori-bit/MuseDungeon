# MuseDungeon 画像アセット仕様

[DESIGN.md](DESIGN.md) §9 の補足。2D レンダラーが要求する画像アセットの**技術仕様**を定める。
画風・配色・個々のデザインは本書では決めない。本書の目的は、画像を別途制作し、コードを変えずに差し込めるようにすることである。

- 第 2 版（2026-11-18）。最初の版は MVP のときのもので、その後のコンテンツと描画の実装に合わせて全体を見直した。変えた点は §12。
- **いま絵にして使われるもの**と、**形だけ決めてあって、まだ描画が対応していないもの**を分けて書く。後者は「未対応」と明記する。未対応の絵は、描画が対応するまで作らない。
- 末尾の §10 に「実装担当の判断に委ねる点」、§11 に「制作の側で決めること」をまとめた。

---

## 1. 基本方針

1. **画像が 1 枚も無くてもゲームは動く。** 既定テーマ `glyph`（色付きタイル＋文字）が全アセットの代替になる。画像テーマは未提供のアセットを `glyph` 表示にフォールバックする。よってアセットは少しずつ追加できる。
2. **ゲーム側は見た目を知らない。** サーバーが送るのはコンテンツ ID と状態だけ。ID から画像への対応は、クライアント側の**テーマ**（画像一式＋マニフェスト）が持つ。
3. **最小要件は「1 種別につき静止画 1 枚」。** 向き・バリエーション・オートタイルは任意の上乗せで、無い場合はレンダラーが手続き的な演出（移動の補間、被弾時の点滅など）で補う。
4. **見た目用の状態はクライアントだけが持つ。** 向きやアニメーションの進行は World State に含めず、イベントから導出する。
5. **絵は情報を運ばない。** 絵で分かることは、そのプレイヤーの画面の文字の表示でも分かること。絵でしか分からないことを作らない（AI と人間を同じに扱うため。音と同じ決まり）。

## 2. グリッドと視点

| 項目 | 仕様 |
|---|---|
| グリッド | 正方形の直交グリッド。1 セル = 1 タイル。アイソメトリック（斜め格子）は対象外 |
| セルサイズ | テーマがマニフェストで宣言する `cellSize`（px、正方形）。**標準は 32×32**。16／24／48／64 も可。1 テーマ内では全アセットが同じ `cellSize` に従う |
| 視点 | 真上、または正面寄りの見下ろし。どちらを採るかは画風の決定事項だが、**1 テーマ内で統一**する |
| 壁 | 壁は 1 セルを占める地形で、セル全体を覆う 1 タイルとして描く。壁の「高さ」のために別セルを使う表現（壁の上面と側面を別セルに分ける方式）は使わない |
| 画面座標 | 左上原点、x は右（東）、y は下（南）。ゲーム座標と一致 |
| 拡大縮小 | レンダラーが表示倍率を決める。補間方法はテーマが `scaling: "nearest" | "linear"` で宣言する |

キャンプの絵（§7.7）だけは、グリッドに乗らない 1 枚絵である。

### 2.1 セルからはみ出すスプライト

- ゲーム上、すべてのエンティティは 1 セルを占有する（複数セルを占める存在は無い。大守護者も 1 セル）。
- 見た目としては、フレームをセルより大きくできる。上限は幅 2 セル・高さ 2 セル。
- 基準点（アンカー）は既定で**フレーム下端の中央**で、これをセル下端の中央に合わせる。アセットごとに `anchor` で上書きできる。
- はみ出しは主に上方向を想定する。重なりは行（y）の小さい順に描くことで解決する（§4）。

## 3. 画像ファイル形式

| 項目 | 仕様 |
|---|---|
| 形式 | PNG、32bit RGBA、sRGB、非乗算（ストレート）アルファ |
| 透過 | 下表のとおり |
| 余白 | フレームの外周に余白や枠線を入れない。フレームは隙間なく並べる |
| 影 | レンダラーは影を描かない。必要ならスプライト内に半透明で含める（フレーム内に収めること） |
| 視界表現 | 「記憶しているが今は見えない」セルの暗転と、未知セルの塗りつぶしはレンダラーが行う。**暗い版・記憶版の画像は不要** |

**透過の要否:**

| 分類 | 透過 |
|---|---|
| 地面系の地形（セル全体を覆うもの。§8.4 の「地面」） | **不透明**。セル全体を塗る |
| 地面の上に載る地形（§8.4 の「載る」） | **透過あり**。下にそのバイオームの床が描かれる |
| 地物・アイテム・キャラクター・モンスター・アイコン | **透過あり** |
| キャンプの絵 | **不透明** |

地面系のタイルは、同じ種別同士（バリエーション含む）で上下左右に並べて継ぎ目が出ないこと。

### 3.1 シートの並べ方

1 アセットにつき 1 つの PNG とする。静止画しかないアセットは PNG 1 枚でよい。

```
          frame0  frame1  frame2 ...   → 横方向 = フレーム（時間順）、またはバリエーション
row 0:    [ ]     [ ]     [ ]          ↓ 縦方向 = 向き
row 1:    [ ]     [ ]     [ ]
```

- 全フレームは同じサイズ（`frame.w × frame.h`）。
- 行の意味は向きの数で決まる（§5）。向きが 1 つなら 1 行。
- 配布時に 1 枚のアトラスへ結合するかどうかは実装の判断で、制作者は気にしなくてよい。

## 4. レイヤー構造

下から上の順に描く。制作するアセットが属するのは L1〜L4 と、L7 のアイコン類である。

| # | レイヤー | 内容 | 画像の出どころ |
|---|---|---|---|
| L0 | 背景 | 未知領域の塗り | レンダラー（テーマの色指定のみ） |
| L1 | 地面 | 床・壁・水・草など、セルを覆う地形 | **アセット**（不透明） |
| L2 | 地形オブジェクト | 扉・階段・格子扉・本棚など、床の上に載る地形 | **アセット**（透過） |
| L3 | 地物・アイテム | 泉・祭壇・護りの火・発見済みの罠、床に落ちているアイテム。同一セルでは地物の上にアイテム | **アセット**（透過） |
| L4 | アクター | プレイヤー・モンスター。行（y）の小さい順に描く | **アセット**（透過） |
| L5 | エフェクト | 命中・回復・飛び道具など | レンダラー（手続き的な演出。画像は未対応: §6.4） |
| L6 | 視界 | 記憶セルの暗転、未知セルの遮蔽、地図の巻物で分かっただけのセル | レンダラー |
| L7 | オーバーレイ | HP バー、状態異常アイコン、接辞バッジ、役割の印（§7.5）、プレイヤー識別マーカー、気配と風の矢印、カーソル、経路表示、ダメージ数字、吹き出し | レンダラー＋**状態異常・接辞のアイコン**（任意） |

- 同一セルにアイテムが複数ある場合は、最上位の 1 つ＋「複数あり」の印（レンダラー描画）とする。
- 装備の見た目への反映（着せ替え）は行わない。キャラクターの画像はクラスごとに 1 種類。
- キャンプにいる間は、L0〜L7 の代わりにキャンプの絵を描く（§7.7）。

## 5. 向き

World State にエンティティの「向き」は無い。向きはクライアントが直近の移動・攻撃イベントの方向から導出する、見た目専用の状態である。

| `facings` | 必要な行 | 用途 |
|---|---|---|
| `1`（既定・**必須はこれだけ**） | 1 行。向きの区別なし | すべてのアセット |
| `2` | 1 行。**東向き（右向き）**で描く。西向きはレンダラーが左右反転する | アクター（任意） |
| `4` | 4 行。上から **南（手前）・西・東・北（奥）** | アクター（任意） |

- ゲームの移動は 8 方向だが、8 方向の画像は要求しない。斜めは左右成分で東西に寄せる（北東・南東 → 東、北西・南西 → 西）。
- 向きを持てるのはアクター（プレイヤー・モンスター）のみ。地形・地物・アイテムは常に `1`。
- まだ動いていないアクターは東向きで描く。

## 6. アニメーション

### 6.1 いま使われるもの

| 対象 | 仕様 |
|---|---|
| `idle` のループ | どの分類でも使える。マニフェストで `frames`（枚数）、`frameMs`（1 枚の表示時間、既定 150）を宣言する。全セル・全個体が同期して再生される |
| 地形 | 既定は静止画 1 枚。任意で `idle` ループ（水面・草など、2〜4 フレーム） |
| 地物 | `idle`（1 フレーム〜）。状態を持つ地物は、状態ごとに静止画 1 枚（§7.6） |
| 扉・格子扉 | 「閉じた」「開いた」「鍵のかかった」は別々の地形 ID で、それぞれ静止画。開閉の中間の絵は不要 |
| アイテム | 静止画 1 枚 |

**どのアセットも、静止画 1 枚があれば成立する。**

### 6.2 手続き的な演出（絵は要らない）

次の動きは、レンダラーが `idle` の絵を動かして表す。制作する絵は無い。

| 出来事 | 演出 |
|---|---|
| 移動 | セル間を補間して動かす |
| 攻撃 | 対象の方向へ小さく突き出す |
| 被弾 | 一瞬点滅させる。ダメージの数字を出す |
| 死亡 | フェードアウト |
| 睡眠 | 睡眠の状態異常アイコン（§7.1 の `status`） |
| 回復・状態異常・レベルアップ・瞬間移動・罠 | 輪や光などの図形 |
| 投擲 | 投げたアイテム自身の絵を、発射元から対象へ飛ばす |

### 6.3 アクターの動きの絵（未対応）

形は次のとおり決めてあるが、**いまのレンダラーは `idle` しか使わない。作っても表示されない。**

| 名前 | 推奨フレーム数 | ループ | 再生の契機 |
|---|---|---|---|
| `move` | 2〜4 | する（移動中のみ） | `entity_moved` |
| `attack` | 2〜4 | しない | `attack` |
| `hurt` | 1〜2 | しない | `damaged` |
| `die` | 3〜6 | しない | `died` |
| `sleep` | 1〜2 | する | 眠っている |

対応させるときは、レンダラーを先に直し、本書の「未対応」を外してから制作する。

### 6.4 エフェクトと UI 部品の絵（未対応）

`fx`（命中・会心・空振り・回復・状態異常・レベルアップ・瞬間移動・飛び道具・罠）と `ui`（カーソル・標的・経路・複数ありの印）は、**いまはすべてレンダラーが図形で描く。絵を作っても表示されない。** 発注表（§9.1）には任意として並ぶが、制作の対象から外す。

## 7. アセット分類と ID

### 7.1 分類と対応するゲーム内データ

| 分類（`class`） | アセットキー | 対応するゲーム内データ | レイヤー | 状態 |
|---|---|---|---|---|
| `terrain` | 地形 ID（例 `core:wall`） | content `terrain` の ID | L1／L2 | 使われる |
| `actor` | モンスター種別 ID（例 `core:goblin`）、クラス ID（例 `core:warrior`） | content `monsters`／`classes` の ID | L4 | 使われる |
| `item` | アイテム種別 ID（例 `core:short_sword`） | content `items` の ID | L3 | 使われる |
| `appearance` | 外見 ID（例 `core:potion_look_03`） | 未鑑定アイテムの外見（§7.4） | L3 | 使われる |
| `feature` | 地物 ID（例 `core:fountain`）、罠 ID | content `features` の ID | L3 | 使われる |
| `status` | 状態異常 ID（例 `core:poison`） | content `statuses` の ID | L7 | 使われる（任意） |
| `affix` | 接辞 ID（例 `core:swift`） | content `affixes` の ID | L7 | 使われる（任意） |
| `scene` | 場面 ID（`scene:camp`） | クライアント固定（§7.7） | 画面全体 | 使われる |
| `fx` | エフェクト ID（例 `fx:hit`） | クライアント固定 | L5 | 未対応（§6.4） |
| `ui` | UI 部品 ID（例 `ui:cursor`） | クライアント固定 | L7 | 未対応（§6.4） |

**原則: アセットキーはコンテンツ ID そのもの。** 敵を 1 種類追加したら、同じ ID のアセットを 1 つテーマに足せば表示される。別途の対応表は要らない。

### 7.2 テーマの置き場所とマニフェスト

- テーマは 1 フォルダ＝ 1 テーマ。場所は `packages/client/public/themes/<themeId>/`。
- `theme.json` がすべての対応を持つ。ファイルパスは自由（ID に含まれる `:` はファイル名に使えないため、キーとパスは別物として扱う）。
- **`packages/client/public/themes/index.json` に登録する**と、画面のテーマの一覧に出る。`kinds` に、そのテーマが持つもの（`image`＝`theme.json`、`sound`＝`sound.json`）を書く。省くと画像のテーマとして扱う。
- 音のテーマ（[SOUND_SPEC.md](SOUND_SPEC.md)）と同じフォルダに置ける。1 つのテーマが画像と音の両方を持ってよい。

```jsonc
// packages/client/public/themes/index.json
[
  { "id": "example", "name": "Example", "kinds": ["image"] }
]
```

```jsonc
// packages/client/public/themes/example/theme.json
{
  "id": "example",
  "name": "Example",
  "formatVersion": 1,
  "cellSize": 32,
  "scaling": "nearest",
  "background": "#000000",
  "fallbackTheme": "glyph",
  "assets": {
    "terrain": {
      "core:floor":                 { "file": "terrain/floor.png", "variants": 3 },
      "core:floor@core:damp_caves": { "file": "terrain/caves_floor.png", "variants": 2 },
      "core:wall":                  { "file": "terrain/wall.png", "autotile": "mask16" },
      "core:shallow_water":         { "file": "terrain/water.png",
                                      "anim": { "idle": { "frames": 4, "frameMs": 250 } } },
      "core:door_closed":           { "file": "terrain/door_closed.png" }
    },
    "actor": {
      "core:goblin":  { "file": "actors/goblin.png", "facings": 2 },
      "core:ogre":    { "file": "actors/ogre.png", "frame": { "w": 48, "h": 64 }, "facings": 2 },
      "core:warrior": { "file": "actors/warrior.png" }
    },
    "item":       { "core:short_sword": { "file": "items/short_sword.png" } },
    "appearance": { "core:potion_look_03": { "file": "items/potion_03.png" } },
    "feature":    { "core:fountain":  { "file": "features/fountain.png",
                                        "states": { "used": { "file": "features/fountain_used.png" } } },
                    "core:ward_fire": { "file": "features/ward_fire.png",
                                        "anim": { "idle": { "frames": 3, "frameMs": 180 } },
                                        "states": { "out": { "file": "features/ward_fire_out.png" } } } },
    "status":     { "core:poison": { "file": "icons/poison.png" } },
    "affix":      { "core:swift":  { "file": "icons/affix_swift.png" } },
    "scene":      { "scene:camp":  { "file": "scenes/camp.png", "fit": "cover" } }
  },
  "categoryFallbacks": {
    "actor":       { "file": "fallback/monster.png" },
    "item:potion": { "file": "fallback/potion.png" },
    "item":        { "file": "fallback/item.png" }
  }
}
```

省略時の既定値: `frame` = `cellSize` の正方形、`facings` = 1、`anchor` = 下端中央、アニメーションなし（静止画）。地形が地面か載るものかは content の地形定義で決まり、マニフェストでは変えない（§8.4）。

### 7.3 解決順

あるエンティティ／セルを描くとき、レンダラーは次の順で探し、最初に見つかったものを使う。

1. **完全一致**: 分類＋ ID（地形のみ、先に `地形ID@バイオームID` を試し、無ければ `地形ID`）
2. **鑑定済みアイテムの外見**: `item` に絵が無ければ、そのアイテムの外見の絵（§7.4）
3. **カテゴリ代替**: `categoryFallbacks`。content の `category`（例 `potion`）を使い、`item:potion` → `item` の順
4. **代替テーマ**: `fallbackTheme`（通常は `glyph`）の同じ ID
5. **組み込みの「不明」表示**

- 画像の読み込み中と読み込みの失敗時は、`glyph` で欠けずに描く。寸法が足りないシートも使わずに `glyph` へ落とす。
- カテゴリ代替のために、クライアントは起動時にサーバーから**公開カタログ**（各コンテンツ ID の分類・カテゴリ・表示名のみ。能力値や出現条件は含まない）を取得する。

### 7.4 未鑑定アイテム（情報隠蔽との関係）

未鑑定の薬・巻物・指輪・護符を「本当の種別」の画像で描くと、正体が画面から漏れる。そのため:

- 未鑑定アイテムは、プレイヤー向けデータでは種別 ID が伏せられ、代わりに**外見 ID**（`appearanceId`）を持つ。レンダラーは `appearance` 分類でこれを引く。
- 外見の一覧（ID と表示名）は content 側で定義する。AI に渡る表示名（「赤い薬」「骨の指輪」など）と、人間が見る画像は同じ外見 ID に紐づくので、**外見の画像はその表示名と矛盾しないように制作する**。
- いまの外見は 19（薬 6・巻物 5・指輪 4・護符 4）。
- 鑑定済みになったアイテムは種別 ID で `item` を引く。そこに画像が無ければ、引き続き外見の画像を使う。**したがって、薬・巻物・指輪・護符は外見の画像だけ作れば足りる**（種別ごとの絵は任意。発注表でも任意になっている）。

### 7.5 個体差と役割の表現（組み合わせごとの画像は作らない）

| 個体差 | 表現方法 |
|---|---|
| 接辞付き・深層強化されたモンスター | 元の種別の画像＋ `affix` のバッジ（L7。2 つまで）。バッジ画像が無ければレンダラーが色付きの印を描く |
| **守護者・大守護者** | **元の種別の画像のまま**。レンダラーが足元の台と冠の印を重ねる。名前は名前表示で出す。守護者ごと・大守護者ごとの絵は作らない（種族も名前もランごとに決まるため） |
| 名前付きの強敵・賞金首 | 元の種別の画像のまま。区別は名前表示と接辞のバッジ |
| 遺物・宝 | アイテムの画像＋レンダラーの印 |
| 接辞付きアイテム | 元の種別の画像のまま。区別は名前表示で行う |
| 複数のプレイヤー | クラスごとの画像＋レンダラーが描く識別マーカー（色付きの輪と名前）。プレイヤーごとの色違い画像は不要 |
| HP の状態 | レンダラーの HP バー（モンスターは 4 段階表示） |
| 状態異常 | `status` のアイコン（L7。3 つまで）。眠っている敵には睡眠のアイコン |
| 背の高い草の中の者 | 隣にいなければ描かれない（見えていないので、そもそも画面に来ない）。草の絵で隠す工夫は要らない |

- 役割の印（台・冠・遺物・宝）は、テーマによらずレンダラーが描く。テーマで差し替える枠は、いまは無い。
- 大守護者と守護者は、いま同じ印である。見分けは名前表示による。

### 7.6 地物の状態

状態を持つ地物は、マニフェストの `states` で状態ごとの絵を出せる。`states` に無い状態は、その地物の基本の絵（`file`）で描く。**基本の絵は、最初の状態の姿で描く。**

| 地物 | 状態（最初 → 変わった後） | 変わった後の絵 |
|---|---|---|
| 泉 `core:fountain` | `idle` → `used` | 涸れた姿。推奨 |
| 祭壇 `core:altar`／賭けの祭壇 `core:gamble_altar` | `idle` → `used` | 任意 |
| 護りの火 `core:ward_fire` | `lit` → `out` | **消えた姿。必須に近い**（消えているかどうかが戦い方に関わる） |
| 碑文 `core:inscription`／書き置き `core:old_note` | `unread` → `read` | 任意 |
| レバー `core:lever` | `up` → `down` | 推奨 |
| 脆い天井 `core:brittle_ceiling` | `intact` → `fallen` | 推奨（崩れた後は瓦礫の姿） |
| 胞子嚢 `core:spore_pod` | `ripe` → `burst` | 推奨 |
| 毒の雲 `core:spore_cloud` | `drifting` のみ | – （半透明で描く。下のアイテムが見えること） |
| 野営の火 `core:camp_fire`（S1。シーズンの参加者が置く） | `lit` のみ | – （ほかの地物・罠・品・敵と同じマスにあることがある。`glyph` テーマは橙の `=`） |
| 罠（毒矢・転移・警報） | 状態なし | – （見つけた罠だけが描かれる） |

- 状態の名前は content の `features` 定義に従う。地物が増えたら、発注表（§9.1）で確かめる。
- **シーズンの印（S2。SEASON.md §18.1）**: 野営の火は上の地物の絵（`feature:core:camp_fire`。発注表に必須で出る）。その上に、レンダラーがマスの右上へ橙の点を重ねる（置いた者の名前はツールチップ）。公開された下り階段と、公開された特別な場所（祭壇・賭けの祭壇・碑文）には、水色の丸に「公」（英語は P）の印を重ねる（`ui:public_mark`）。道しるべ（入口から公開された階段までの道）は、地図の巻物と同じ「地形は分かっているが、まだ見ていない」マス（紫がかった暗さと斜線）として描く（`ui:trail`）。`ui:public_mark`・`ui:trail` は、ほかの `ui` と同じく未対応（図形で描く。絵を作っても表示されない）で、発注表には「未対応」と出る。
- `glyph` テーマは、いま `used` だけを暗く描く。ほかの状態の描き分けは実装担当に委ねる（§10）。

### 7.7 キャンプの絵

**目的**: プレイヤーがキャンプにいる間（遠征と遠征の間）、地図の代わりにキャンプの絵を見せる。いまは、キャンプにいても最後にいた階の地図が見え続けている。

**画面の動き**:

| 項目 | 仕様 |
|---|---|
| いつ出るか | そのプレイヤーの状態がキャンプ（`at_camp`）のとき。地図を描く場所の全体に、キャンプの絵を描く。地図（L0〜L7）は描かない |
| 上に重なるもの | キャンプのパネル（遠征の候補・記録・引退）。今までどおり、絵の上に出る |
| 遠征を始めたとき | 地図に戻る |
| 観戦・リプレイ | 見ている相手のプレイヤーがキャンプにいれば、同じくキャンプの絵 |
| 俯瞰（全体を見る観戦） | 今までどおり地図。キャンプの絵は出さない |
| 協力プレイ | 各自の画面で決まる。キャンプにいる人にはキャンプの絵、潜っている人には地図 |
| 終わったラン（死亡・引退） | 今までどおり（キャンプの絵は出さない） |
| 絵が無いテーマ・`glyph` | 地図の代わりに、背景色の無地と「キャンプ」の文字。**地図を隠すことは、絵が無くても行う** |

**絵の仕様**:

| 項目 | 仕様 |
|---|---|
| キー | `scene` 分類の `scene:camp` |
| 枚数 | 1 枚（必須はこれだけ） |
| 大きさ | グリッドに乗らない 1 枚絵。**推奨 1280×720（16:9）**。`cellSize` に従わなくてよい |
| 透過 | 不透明 |
| 合わせ方 | `fit: "cover"`（既定。描く場所を覆うように拡大し、はみ出しは中央基準で切る）か `"contain"`（全体を収め、余りは `background` の色） |
| 切れてよい範囲 | 画面の縦横比は端末で変わる。**大事なものは中央の 60%（幅・高さとも）に描く**。外側は切れることがある |
| パネルとの重なり | キャンプのパネルが中央に重なる。絵は背景として成り立つこと（パネルの後ろに隠れても困らない構図にする） |
| 動き（任意） | `anim.idle` で 2〜4 フレームのループ（焚き火の揺れなど）。横にフレームを並べる。1 フレームは絵全体と同じ大きさ |
| 画風 | 地図の絵と同じ視点である必要はない（横から見た野営の絵でよい） |

**やらないこと**:

- キャンプの絵に、プレイヤーのキャラクターや持ち物を重ねて描くこと（クラスの絵は地図用の小さなスプライトで、1 枚絵とは大きさも視点も合わない）。
- 到達した深さ・確定点・遠征の回数などで絵を変えること。変える枠は設けない（足したくなったら、§1 の 5 のとおり「その情報は画面の文字に出ているか」を確かめてから、本書に足す）。

**実装（2026-11-18）**: `packages/client/src/ui/camp.tsx`（`CampScene`）。遊ぶ画面・観戦（追従）・リプレイ（追従）で、地図の上に重ねて地図を隠す。キャンプのパネルと、観戦の印（AI の応答待ち・「〇〇はキャンプにいる」）はその上に出る。

- 切り替えの演出: キャンプの絵は 0.4 秒で現れる（フェードイン）。遠征を始めたら、すぐ地図に戻る。
- キャンプのパネルの後ろの暗い幕は、絵が見えるよう薄くした（パネル自体は不透明のまま）。
- 絵が無いときの文字は、左下に大きく「キャンプ」。背景はテーマの `background`。
- **キャンプにいる間に地図を見返す手段は設けない。** 地図の中央はキャンプのパネルで覆われるので、絵を外しても見返しの役に立たない。前の遠征の地図は、リプレイ（巻き戻し）で見られる。
- 見本のテーマ `sample` に、検証用のダミーのキャンプの絵（2 フレームの焚き火の揺れ）を入れた。

## 8. 地形の追加仕様

### 8.1 バリエーション

`variants: N` を指定すると、PNG に N 枚を横に並べ、セルごとに 1 枚を選ぶ。選択は座標から決まる見た目専用のハッシュで行い（ゲームの乱数は使わない）、同じセルは常に同じ絵になる。アニメーションと併用する場合は、縦方向をバリエーション、横方向をフレームとする。

### 8.2 オートタイル（任意）

壁や水の縁を隣接関係に応じて描き分けたい場合のみ使う。指定しなければ 1 枚の絵を全セルに使う。

- `autotile: "mask16"`: 上下左右 4 方向の隣が「同じグループ」かどうかの 4 ビットで 16 枚を引く。
- ビット: 北 = 1、東 = 2、南 = 4、西 = 8（同じグループなら立てる）。PNG には index 0〜15 の順に横 16 枚を並べる。
- 未知のセルは「同じグループ」として扱う（探索が進むたびに壁の絵が変わるのを抑えるため）。
- バリエーションとは併用しない。

### 8.3 バイオームによる差し替え

同じ地形 ID でも、バイオームごとに別の絵を使える（`地形ID@バイオームID`）。無ければ共通の絵を使う。したがって最小構成は「共通の床と壁を 1 組」で、バイオームごとの絵は後から足せる。

いまのバイオームは 4 つ: `core:stone_halls`（石の広間）、`core:damp_caves`（湿った洞窟）、`core:overgrown_ruins`（苔むした遺跡）、`core:sunken_archive`（沈んだ書庫）。

### 8.4 いまの地形と、地面か載るものか

| 地形 | ID | 扱い | 制作の注意 |
|---|---|---|---|
| 床 | `core:floor` | 地面 | 載る地形の下にも描かれる |
| 壁 | `core:wall` | 地面 | |
| 浅い水たまり | `core:shallow_water` | 地面 | |
| 草地 | `core:grass` | 地面 | |
| 背の高い草 | `core:tall_grass` | 地面 | 視界を遮る。草地と見分けが付くこと |
| 瓦礫 | `core:rubble` | 地面 | |
| 柱 | `core:pillar` | 地面 | **不透明で、床ごと描く。** バイオームで床の絵を変えるなら、柱もバイオームごとに用意する（`core:pillar@バイオームID`） |
| 閉じた扉・開いた扉 | `core:door_closed`・`core:door_open` | 載る | |
| 下り階段・上り階段 | `core:stairs_down`・`core:stairs_up` | 載る | 上りと下りの見分けが付くこと |
| 格子扉（閉じた・開いた・鍵のかかった） | `core:grate_closed`・`core:grate_open`・`core:grate_locked` | 載る | 閉じた格子は向こうが見える（視界を遮らない）。鍵のかかったものは見分けが付くこと |
| 本棚 | `core:bookshelf` | 載る | 視界を遮る |

地形が増えたら、発注表（§9.1）と content の地形定義（`layer`）で確かめる。

### 9.1 チェックリストと検証ツール

制作と実装を切り離すため、次の 2 つがある。

- `npm run assets:checklist`: 現在のコンテンツ定義から、必要なアセットキーの一覧（分類・ID・表示名・必須／任意／未対応）を出力する。制作の発注表になる。`-- --format json` で JSON（`required` と `supported`。`supported: false` は未対応）。
  - キャンプの絵は `scene` の `scene:camp`（必須）。
  - `fx`・`ui` は「未対応（作らない）」と出し、必須・任意の数に入れない（§6.4）。
- `npm run assets:check -- <テーマのフォルダのパス>`（例: `packages/client/public/themes/sample`）: テーマを検証する。未提供の ID、マニフェストにあるが content に無い ID、PNG の寸法が合わないもの、不透明であるべき地面タイルの透過、を報告する。
  - キャンプの絵: 不透明か、幅がフレーム数で割り切れるか、1 フレームが 16:9 か（違えば警告。推奨 1280×720 でなければ情報）、`fit` が `cover` か `contain` か。グリッドの寸法は問わない。
  - `fx`・`ui` の絵がマニフェストにあれば「未対応。表示されない」と警告する。

見本として、検証用のダミー画像のテーマ `sample` がある（床・壁・ゴブリン・戦士・薬 1 つと、キャンプの絵）。

## 10. 実装担当の判断に委ねる点

- PNG を実行時に個別に読むか、ビルド時にアトラスへ結合するか（結合する場合の縁の処理を含む）。
- 手続き的な代替演出の具体値（補間時間、点滅の色、フェード時間）と、高速リプレイ時にどの演出を省くか。
- `glyph` テーマの文字・色の割り当てと、地物の状態の描き分け。
- `mask16` より細かいオートタイル（角を含む方式）を追加するかどうか。追加する場合は `autotile` の新しい値として足し、既存の値の意味は変えない。
- 公開カタログの取得経路と、テーマの切り替え UI。
- マニフェストの細部（キー名など）。変更する場合は本書を更新し、`formatVersion` で互換性を管理する。
- キャンプの絵（§7.7）: `scene` 分類の読み込み、地図との切り替えの演出（フェードなど）、キャンプにいる間に地図を見返す手段を設けるかどうか、発注表と検証ツールへの `scene` の追加。

**実装に求めること（本書の第 2 版で新しく求めるもの）**: どちらも実装済み（2026-11-18）。

1. キャンプにいる間、地図を隠してキャンプの絵（無ければ無地と文字）を出す（§7.7）。切り替えはフェードイン、地図を見返す手段は設けない（§7.7 の「実装」）。
2. 発注表と検証ツールに `scene:camp` を足し、`fx`・`ui` は「未対応」と分かる形にする（§9.1）。

**本書の外で残っている、人間の画面の課題**（絵の仕様ではないので、ここでは決めない）:

- 敵の予備動作（構え）は、横のパネルに文字で出るだけで、地図の上には出ない。大鬼の大振りが狙うマスも地図に出ない。地図に出すなら、レンダラーの印として足す（絵の枠にするかは、そのとき決める）。
- 大守護者と守護者の印が同じである。
