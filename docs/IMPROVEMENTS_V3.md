## 0. 受け止め

二つの意見は同じ結論に着く。**技術基盤と遠征の枠は機能している。足りないのは枠の中身で、「続けたい理由」がまだ無い。**

維持するもの（報告で評価された点）: ブリーフィング、ヘッダ 2 行、理由付きの `valid_actions`、末尾の `▶` 行、撃破で最大 HP が分かる仕組み、マクロの実績表示、ヒント付きエラー、休憩の見積もり。

### 0.1 現行実装で確認したこと

| 意見 | 確認結果 |
|---|---|
| 投擲が外れても何も出ない／射線が無い相手も候補に出る | 事実。`item_thrown` は `hit: null` になるだけで文章が命中時と同じ。経路が壁で切れると足元に落ちる。候補は `hostiles[0]` の 1 体だけを、射線を見ずに出す（`observation.ts:603`） |
| 撃破が「見えなくなった敵」になる／再出現が「新たな敵」になる | 事実。`diffChanges` は前回と今回の視界内 ID の差だけを見ている（`turn.ts:109-117`） |
| 推定残り HP が断定的に外れる | 事実。`hpLeftEstimate` は「倒した個体の最大 HP の範囲」を種族の範囲そのものとして扱う。1 体しか倒していなければ幅が 0 になる |
| 地図の文字が重なる | 事実。英語名の頭文字を大文字にしているだけ（`observation.ts:253`） |
| 目的達成の瞬間に帰るのが最善 | 事実。スコアは深度 1 階 1000 点・撃破 10 点・レベル 25 点・遠征の基礎点で、目標階に残る理由も、目標より深く潜る理由も無い。キャンプで全快し、同じ階段から再開する |
| 成長に選択が無い／職業の個性が出ない | 事実。レベルアップは `classes.levelUp` の固定成長だけ。能動技は無い。装飾品の枠はあるが、装飾品のアイテムが 1 つも無い。投擲は誰が投げても同じ命中 |
| スコア・記録が見えない | 事実。スコアは `summary` と HTTP の `leaderboard` にしか出ない。MCP から引く手段が無い |
| 階ごとの違いが無い | 事実。バイオームの差は地形の見た目と出現の重みだけ。泉と祭壇以外に操作できる地物が無い。モンスター・アイテム・バイオームに描写文が無い |
| 守護者・遺物が薄い | 事実。守護者は通常モンスター＋能力値の接辞 1 つ。遺物は効果の無い専用アイテム |

### 0.2 この版の設計方針

1. **動機は構造から作り、助言はしない。** v2 と同じく、ゲームが出すのは事実と選択肢だけ。「粘るべき」とは書かず、粘った場合に何が得られ何を失うかが観測から読めるようにする。
2. **選択は観測に見えて初めて選択になる。** 新しい仕組みはすべて「観測のどこに、どんな事実として出るか」まで決める。見えない報酬は存在しないのと同じ（指摘 C）。
3. **中身はデータで増やす。** 新しい仕組みはレジストリ＋データ定義にし、以後の追加はデータ 1 件で済むようにする。
4. **既存の不変条件は一つも緩めない。** ランをまたぐ情報は World の外に置き、World へ入れるときは必ずコマンドとイベントを通す（§7.3）。

## 1. 観測と操作の修正

コンテンツを足す前に直す。ここは仕様の穴であり、設計判断は少ない。

### 1.1 投擲

- **結果を必ず文章にする。** `item_thrown` に `outcome: 'hit' | 'missed' | 'blocked' | 'fell_short' | 'no_target'` と `blockedBy?: 'terrain' | 'actor'` を足す（after 値。reducer は使わない）。文章の例:「投げナイフは投石兵に当たらず (9,6) に落ちた」「投げナイフは壁に当たり (10,7) に落ちた」。落下地点は必ず書く。
- **射線を観測に出す。** 射線の計算はルールなので engine が行い、結果を知識に書く。`knowledge.shots: EntityId[]`（自分のセルから投擲の経路が通る、視界内の敵）を `knowledge_updated` に足す。観測は `visible.monsters[].shot: 'clear' | 'blocked'` として出す。
- **候補は射線が通る相手だけ。** `valid_actions` の `throw_item` は `shot: 'clear'` の相手ごとに出す（近い順に最大 3）。自分を撃っている相手を優先して並べる。
- **通らない相手を ID で狙ったら拒否する。** `no_line_of_sight`（既存コード）を返し、手番を消費しない。座標を狙う投擲は従来どおり通す（遮られた位置に落ちる）。
- 鑑定済みで `onUse` が自分に害のある薬は、`use_item` ではなく `throw_item` を候補に出す（アイテム定義に `harmful: true`）。

### 1.2 投げた物の回収

- 投げた物に `item.thrownBy: PlayerId` を付ける。**自分が投げた物のあるセルに入ると、移動の一部として拾う**（追加の手番なし。所持品が満杯なら拾わない）。AI・人間とも同じ。
- マクロ `collect` を足す: 既知の「自分が投げた物」を近い順に回って拾う。中断条件は `travel_to` と同じ。結果に拾った数と残りの数を付ける。

### 1.3 変化欄（`turn.changes`）とマクロの停止

- `killed`（あなたが倒した）と `died_seen`（目の前で他の理由で死んだ）を足す。`hostile_gone` は撃破以外で視界から消えたときだけ。優先順は `hp_low` の次。
- 既知の個体（`knowledge.met` にある ID）が再び見えたときは `reappeared`（弱い変化）。`new_hostile` は、このランで初めて見る個体だけ。
- マクロが敵で止まる条件を次のとおりにする（engine とマクロ展開の両方）。
  1. このランで初めて見る敵が視界に入った。
  2. 既知の敵が、**追跡中かつ逃走中でない**状態で視界に入った。
  3. 視界内の敵が追跡中に変わった（眠っていた敵が起きた、未察知の敵に気づかれた）。
  4. ダメージを受けた、または自分を狙った攻撃が外れた。
  - 逃走中の個体の出入りでは止まらない。`rest` は従来どおり、敵が視界に入れば状態によらず止まる（ルール文をこの挙動に合わせる）。
- **行動結果の `outcome` は、その行動から次の自分の手番までに受けた被害の合計を必ず含める。** 例:「…2 回攻撃を受け、合計 7 ダメージ（HP 21→14）」。外れた攻撃も回数だけ書く。

### 1.4 見えない相手の方向

`masks` で攻撃者を伏せたイベントにも、被害者にだけ `fromDir`（8 方向）を残す。文章は「南東から石が飛んできた」。位置・種別・ID は伏せたまま。

### 1.5 推定残り HP

- `hp_left_est` に `samples`（根拠にした撃破数）を足す。
- `samples < balance.estimate.minSamples`（初期値 3）の間は、**記録の最大値を上限として使わない**。4 段階表示と `damage_seen` と「記録の最小値」だけで下限を出し、上限は `null`。文章は「推定残りHP: 3 以上（記録 1 体）」。
- `min == max` のときは「3」と書く。

### 1.6 地図

- 英字の割り当てを種族ごとに一意にする。**カタログで種族に固定の 1 文字**を持たせる（`monsters.glyph`。重複は起動時の検証で落とす。接辞付きも同じ文字）。プレイヤーは `@`、他プレイヤーは `&`。
- 地図に目盛りを付ける（上に列番号の 1 の位と 10 の位、左に行番号）。字下げは行番号に置き換える。フロア外の行と列は出さない（座標が負になる表示をやめる）。
- 同じセルの同種アイテムは 1 行（`投げナイフ x3 (8,5)`）。記憶の中の遠いアイテムは近い順に 5 件まで、残りは「他 N 件」。

### 1.7 文章と照会

- 拾う・装備・外すの文章は接辞付きの表示名を使う。
- 遠隔攻撃の動詞を命中・外れで統一する（「〜の射撃。あなたは 2 ダメージを受けた」）。
- 見出し「見えるもの:」は内容が 1 件でも出す。
- `look` と `recall` は、思い出にある戦闘情報を全部返す: 速さの区分（遅い／普通／速い。`abilities` の `fast`・`slow` から）、遠隔攻撃の有無と観測した最長距離、受けた・与えた最大ダメージ、体力の記録。能力タグは `locale` の言葉で出す（`flees` →「手負いで逃げる」）。
- `self` に自分の速さ（`speed`）を出す。
- `get_rules` に `classes` のトピックを足し、職業の一覧・初期装備・成長・能動技（§4）を公開カタログから生成する。`new_run` の `class` が不正なときのエラーにも一覧を付ける。
- キャンプの観測は専用の形にする: 足元・未探索・地図・階の表示を出さず、成績（§2.6）と候補（§2.5）だけ。

### 1.8 トークン量

`new_run`／`resume_run` の引数と、いつでも呼べる `set_options` で、プレイヤーごとに選べるようにする（ゲームには影響しない。人間向け UI には関係しない）。

| オプション | 値（既定が先頭） | 内容 |
|---|---|---|
| `map` | `auto` / `always` / `never` | `auto` は、階が変わった・新しいセルを知った・敵の出入りがあった応答にだけ地図を付ける。付けないときは「地図: 変化なし」の 1 行 |
| `inventory` | `on_change` / `always` | 所持品の行は変わったときだけ |
| `status_line` | `short` / `long` | `▶ あなたの番（手番 N）`。長い説明は `new_run`・`resume_run`・状態が変わった応答だけ |

装備の行は削り、所持品の `*` に一本化する。`brief_map` は `map` に置き換える（旧引数は受け付けて読み替える）。

## 2. 戦利品と確定（粘るか帰るか）

### 2.1 考え方

いまの遠征は「目的を達成したら帰る」の一択になる。これを、**遠征中に得た点は持ち帰って初めて確定する**構造に変える。目的の基礎点も、深追いの点も、拾った宝も、すべて「未確定の戦利品」として積み上がり、帰還で確定し、死ねば失う。欲張るほど賭け金が増える。

### 2.2 スコア（版 2）

```
ランのスコア = 確定点の合計（終了した遠征の払い戻しの合計）
遠征の払い戻し:
  帰還（目的達成）  戦利品 × 条件の倍率（§2.5）
  撤退（未達成）    戦利品 × withdrawPct（初期値 50%）。目的の基礎点は含まれない
  死亡・引退        0（失った戦利品として記録に残す）
```

戦利品の内訳（係数はすべて `balance.json` の `haul`）:

| 項目 | 加算の条件 | 初期値 |
|---|---|---|
| 目的 | 目的を達成した | 現行の基礎点（2000／3000／3500、深さで加算） |
| 深追い | この遠征で、目標より深い階に初めて着いた | 1 階目 +600、以後 +300 ずつ増える（+600、+900、+1200…） |
| 宝 | 分類 `treasure` のアイテムを**所持している**（落とせば減る） | アイテムごとの `value`（§2.3） |
| 賞金 | 名前付きの強敵・守護者を倒した | 個体ごとの `bounty`（§3・§5.5） |
| 発見 | このランで初めて: 種族を倒した／アイテム種を鑑定した／特殊部屋を見つけた／碑文を読んだ | +50／+30／+100／+50 |
| 撃破 | 敵を倒した | 1 体 +10（現行どおり） |

- 深度 1 階 1000 点とレベルの点は廃止する（深さは目的と深追いが評価する）。
- 記録は `scoreVersion: 2` を持ち、版 1 の記録とは別の表にする。並び順は「確定点」、同点なら「達成した遠征の数」「最深」。
- 目的が `reach_depth` でも、目標階を探索する理由（宝・発見）と、さらに潜る理由（深追い）が生まれる。

### 2.3 宝（`treasure`）

- 新しいアイテム分類。使い道は無く、点としての `value` だけを持つ。**見えた時点で価値が分かる**（「銀の杯（価値 180）」）。所持枠を 1 つ使うので、薬や投擲物との取り合いになる。
- 出どころ: 宝物庫（§5.1）、守護者と名前付きの強敵の確定ドロップ、階の異変（§5.3）、通常の床には低確率。
- 定義は `items.json`（`category: "treasure"`, `value: "2d6*10"`, 深度で伸びる）。初期は 6 種。

### 2.4 目的を達成した後の圧力

- `slay_guardian` と `retrieve_relic` は、達成の瞬間から**その遠征の間、徘徊の湧き間隔が半分**になる（`balance.expedition.afterObjective.wanderIntervalPct: 50`）。ルールとして公開し、発生時に「坑が騒がしくなった」と `changes` に出す。
- 遺物は拾った瞬間にその階の眠っている敵が起きる（§3.3）。
- `reach_depth` には追加の圧力を付けない（穏当な選択肢として残す）。

### 2.5 遠征候補の性格と危険度

キャンプの 3 候補を、役割の違う 3 枠にする。

| 枠 | 目標深度 | 条件 | 性格 |
|---|---|---|---|
| 堅実 | 最深 +1〜2 | なし | 低い基礎点 |
| 標準 | 最深 +2〜3 | 0〜1 個 | 現行相当 |
| 野心 | 最深 +3〜4 | 1〜2 個 | 高い基礎点と倍率 |

**条件（`expeditionTraits`）** は、目標階までの全階に効く公開の修飾で、データで定義する。倍率は帰還時の戦利品に掛かる。初期の 6 種:

| ID | 効果（すべて公開） | 倍率 |
|---|---|---|
| `crowded` | 敵の密度 +50%、宝の密度 +50% | ×1.2 |
| `restless` | 徘徊の湧き間隔 −40% | ×1.2 |
| `dim` | 自分の視界 −2 | ×1.25 |
| `scarce` | 床のアイテム密度 −50% | ×1.2 |
| `elite` | 名前付きの強敵が各階に 1 体 | ×1.15（賞金は別） |
| `quiet` | 徘徊なし。泉は出ない | ×0.9 |

**危険度**は、公開の式だけで出す（隠し情報を使わない）。

```
推奨レベル(深度) = 1 + floor(深度 × 3 / 4)        // balance.expedition.recommendedLevel
危険度 = clamp(3 + (推奨レベル(目標深度) − 自分のレベル) + 条件の危険度の合計, 1, 5)
```

候補の表示（キャンプの観測と `expedition`）:

```
2) [野心] 地下7階の守護者「灰を呼ぶ者ヴォルン」を倒して帰還
   基礎 +4500 / 倍率 ×1.2（群れる階層）/ 危険度 4（推奨 Lv6、あなたは Lv3）
   守護者: オークの荒くれ・呼び集める者（あなたの記録: 遭遇 0）
```

守護者の種族・名前・型（§3.1）は候補を作る時点で決め、候補に出す。自分の思い出にその種族があれば、遭遇数・撃破数を 1 行添える。

### 2.6 見え方

観測の `expedition` に戦利品を足す。ヘッダの 2 行目にも 1 行で出す。

```ts
expedition.haul: {
  total: number                    // 未確定の戦利品の合計（倍率を掛ける前）
  multiplier_pct: number           // 条件の倍率
  parts: { objective, overreach, treasure, bounty, discovery, kills }
  if_extract_now: number           // 今 extract した場合に確定する点（帰還／撤退の別は extract_outcome）
  next_overreach: { depth: number, points: number }   // 次に深追いの点が入る階とその点
}
self.score: { banked: number, expeditions_completed: number }
```

テキストの例:

```
遠征2 [達成] 戦利品 4,180（目的3000・宝680・発見300・撃破200）×1.2 → 今帰れば +5,016 / 地下7階に着けば +900 / 確定済み 2,400
```

「今帰れば」と「次に進めば」の両方が事実として並ぶ。どちらを選ぶかは書かない。

### 2.7 COOP

宝は持っている本人の戦利品。目的・深追い・発見・賞金は遠征の参加者で共有し、帰還した人に確定する。死んだ人の分は失う。

## 3. 守護者・遺物・節目

### 3.1 守護者の型

守護者を「能力値が高い通常モンスター」から、**種族 × 型（signature）× 弱点 × 棲み処**の組に変える。型はデータ（`guardians.json`）で定義し、振る舞いは既存のレジストリ（AI archetype・effect）に小さなハンドラを足して実現する。

| 型 ID | 称号 | 振る舞い | 読み合い |
|---|---|---|---|
| `summoner` | 呼び集める者 | HP が 75%・50%・25% を切るたびに、その階の種族から手下を 2 体呼ぶ | 手下を先に片付けるか、本体を一気に削るか |
| `charger` | 突き進む者 | 直線上に相手がいると 1 手「構える」。次の手番に直線を突進し、当たれば 2 倍ダメージ。外れると 1 手無防備 | 構えを見たら軸をずらす。柱の陰に誘う |
| `warded` | 護られし者 | 棲み処の「護りの火」2 基が灯っている間、装甲 +4。火は `interact` か投擲で消せる | 戦う前に火を消すか、消しながら戦うか |
| `enrager` | 荒ぶる者 | HP 50% 以下で速さ +30・威力 +2。怒る 1 手前に予兆 | 半分まで削る前に準備を終える。逃げて仕切り直す |
| `stalker` | 潜む者 | 視界外へ退いて回り込み、背後から襲う。睡眠しない | 通路に陣取る。扉を閉める |

- **予備動作（intent）を公開情報にする。** 次の手番に大きな行動を取る敵は、視界内なら `visible.monsters[].intent`（`winding_up`・`summoning`・`enraging` と 1 行の文章）で分かる。engine が `ai_state_changed` に載せ、EntityView に射影する。守護者に限らず、通常の敵にも使える仕組みにする。
- **弱点**は型と独立に 1 つ付く（`weaknesses`: 毒に弱い／投擲に弱い／眠りが深い（気づかれる前の一撃が必ず会心）／水場で遅い）。弱点は**最初は伏せる**。知る手段は、目標階までの階に置かれる碑文（§5.1）と、実際に試して観測すること。知った弱点は `knowledge.guardianIntel` に入り、`look`・`expedition` に出る。
- **棲み処**は型ごとの prefab（柱・護りの火・水場など、その型の読み合いが成立する地形）。目標階の生成で `objective` ストリームを使って置く。
- **名前**は音節表（`names.json`）からシードで作る（「灰を呼ぶ者ヴォルン」）。既存作品の固有名は使わない。
- 守護者は宝（戦利品）と賞金を必ず落とす。
- 種族・型・弱点・名前は候補を作る時点で `hash(runSeed, 'expedition', 通番)` から決める（状態を持たない）。種族と型と名前は候補に出し、弱点は出さない。

### 3.2 節目の大守護者

- 深度 5 の倍数に、専用の floorType `core:warden_hall`（小さな階。棲み処と前室だけ）を置き、**大守護者**がいる。型を 2 つ持ち、弱点は 1 つ。
- 大守護者の階は「次の節目」としてキャンプと `expedition` に常に出す（「次の節目: 地下5階の大守護者（未踏破）」）。遠征の目的とは独立で、遠征候補の目標が節目をまたぐ場合は必ずこの階を通る。
- 倒すと大きな賞金と、**加護の選択**（§3.3 の加護から 3 つ提示、1 つ選ぶ）。倒さずに下りる道は無い（下り階段は棲み処の奥）。
- これが長期の目標の柱になる: 短期（目の前の敵）／中期（遠征の目的）／長期（次の節目、記録、図鑑）。

### 3.3 遺物と加護

- 遺物を「効果の無い専用アイテム」から、**個別の遺物（`relics.json`）**に変える。それぞれ名前・由来の一文・**加護**を持つ。
- 遠征を達成して持ち帰ると、遺物は加護になり、**そのキャラクターにランの終わりまで付く**。遠征の成功が次の遠征を質的に変える。
- 初期の 8 種（効果は既存の能力値・状態異常・effect で表現できるものに限る）:

| 遺物 | 加護 |
|---|---|
| 息吹の欠片 | 自然回復の間隔 −2 |
| 狩人の欠片 | 投げた物が当たったとき 50% で手元に戻る |
| 灯の欠片 | 視界 +1 |
| 鎮めの欠片 | 眠っている敵が起きる確率が半分 |
| 鋼の欠片 | 装甲 +1 |
| 俊足の欠片 | 階段を使った直後の 10 手番、加速 |
| 目利きの欠片 | 薬と巻物の手がかり（§5.4）が最初から見える |
| 執念の欠片 | 致死ダメージを 1 遠征に 1 回だけ HP 1 で耐える |

- **持ち出しは仕事になる。** 遺物を拾った瞬間、その階の眠っている敵がすべて起き、遺物の位置へ向かう（公開ルール。拾う前の `valid_actions` に「(階が目覚める)」と注記）。拾う前に退路を決める遊びになる。
- どの遺物かは候補の時点で名前と加護を公開する（どれを取りに行くかがビルドの選択になる）。
- 加護は `self.boons` に出す。World では `Entity.boons: string[]`。

### 3.4 物語の枠

世界観の最小限の枠を置く。文面はすべてデータ（`lore.json`・各定義の `desc`）で、差し替えられる。

- 枠の案: **地の底に沈んだ記録庫の都。層は潜るたびに形を変え（＝自動生成）、番人は記憶の欠片（＝遺物）を守っている。潜る者は欠片を持ち帰り、忘れられたものを取り戻す。** プレイヤーが学んだこと（思い出・図鑑）が「取り戻した記憶」に当たる。
- ブリーフィングに一文の物語を足す。型・バイオーム・遺物のタグから定型文を選ぶ（「苔むした遺跡の奥で、灰を呼ぶ者が目を覚ました」）。
- 碑文で読める断章（§5.1）は、物語の断片であると同時に、守護者の弱点や階の仕掛けの手がかりを含む。読んだ断章は図鑑（§7.2）に集まる。
- この枠と文面の採否は依頼者に確認する（§12）。仕組みは枠に依存しない。

## 4. ビルド

### 4.1 レベルアップの選択

- 固定成長（HP）は残し、**レベルが上がるたびに特技を 1 つ選ぶ**。候補は 3 つ。職業の特技表と共通の特技表から、`hash(runSeed, 'perk', playerId, level)` で選ぶ（状態を持たない。取得済みと前提を満たさないものは除く）。
- 選択は手番を消費しないコマンド `choose_perk {option}`。**選ぶまで進行は止めない**（保留できる。`alerts` に `perk_pending`、`valid_actions` に 3 候補と説明）。COOP でも他人を待たせない。
- 現行の `accEvery`・`mightEvery`・`evaEvery` の自動成長は廃止し、特技に置き換える。
- 特技はデータ（`perks.json`）: 能力値の修正、能動技の習得、条件付きの修正（既存の接辞と同じ `mods`・`onHit` の形）。初期の表:

| 系統 | 特技 |
|---|---|
| 共通 | 頑健（最大 HP +5）／精密（命中 +1）／剛力（威力 +1）／身軽（回避 +1）／荷運び（所持枠 +4） |
| 戦士・前衛 | 強打（能動技）／なぎ払い（能動技）／盾の構え（待機した次の被弾を装甲 +2）／踏みとどまる（HP 25% 以下で威力 +2） |
| 戦士・不屈 | 立て直し（能動技）／鉄の胃（毒の手番が半分）／威圧（隣接した敵の逃走の閾値 +25%） |
| 斥候・射手 | 狙い撃ち（能動技）／早投げ（投擲の手番コスト 70）／回収の手（投げた物を拾う範囲が隣接まで広がる） |
| 斥候・影 | 忍び足（気づかれる確率 −20%）／不意打ち（気づいていない敵への近接が必ず会心）／身をかわす（能動技） |

### 4.2 能動技

- 新しいコマンド `ability {id, target?}`（MCP ツール `use_ability`）。資源は増やさず、**再使用までの手番（cooldown）**だけで管理する。定義はデータ（`abilities.json`: 対象の取り方、コスト、cooldown、effect の列）。
- `valid_actions` に、使えるものは対象付きで、使えないものは残り手番付きで出す（`use_ability bash -> e_xxx` / `use_ability bash (あと3手番)`）。`self.abilities: { id, name, cooldown_left }[]`。
- 初期の能動技:

| ID | 効果 | cooldown |
|---|---|---|
| `bash` 強打 | 近接攻撃。当たれば 1 手番の朦朧（行動不能） | 8 |
| `cleave` なぎ払い | 隣接する敵すべてに近接攻撃 | 6 |
| `second_wind` 立て直し | 最大 HP の 25% を回復 | 遠征に 1 回 |
| `aimed_throw` 狙い撃ち | 投擲。命中 +4、気づいていない相手には会心 | 5 |
| `slip` 身をかわす | 2 マス移動し、その手番は隣接した敵に攻撃されない | 10 |

- 各職業は Lv1 で能動技を 1 つ持つ（戦士: 強打、斥候: 狙い撃ち）。
- 状態異常 `stun`（朦朧）を足す（既存の `incapacitate` ハンドラ）。

### 4.3 職業の差を戦い方に出す

- `classes` に `proficiency: { melee, thrown }`（命中の修正）を足す。戦士は投擲 −2、斥候は投擲 +2・近接 0。戦士が投げナイフだけで戦うのは「できるが損」になる。
- 3 つ目の職業は、この版では足さない（特技の 2 系統 × 2 職業で 4 通りの育て方が出るかを先に確かめる。§10 の計測）。

### 4.4 武器の特性と装飾品

- 武器に `traits`（レジストリ）を足す。

| 特性 | 効果 | 付く武器 |
|---|---|---|
| `quick` | 攻撃の手番コスト 70 | 短剣 |
| `reach` | 2 マス先の敵を攻撃できる（間のセルが通れること） | 槍（新規） |
| `sweep` | 攻撃が、対象に隣接しかつ自分に隣接する敵 1 体にも当たる | 戦斧 |
| `crush` | 当たれば 20% で朦朧 | 鎚矛 |
| `balanced` | 特性なし（命中 +1） | 小剣 |

- 装飾品（`accessory`）を 6 種足す。すべて未鑑定（外見名）。効果は得失の組にする（例: 見張りの指輪＝視界 +1・回避 −1／狂戦の護符＝威力 +2・装甲 −1／静寂の指輪＝気づかれにくいが、自分の騒音で起きた敵は必ず追跡する）。
- **呪い**: アイテム接辞 `cursed` を足す。未鑑定の武器・防具・装飾品に低確率で付き、**装備するか鑑定するまで見えない**。呪われた装備は外せず（解く手段: 祭壇、解呪の巻物）、能力は同種より 1 段強いが、欠点が 1 つ付く。「強いかもしれないが外せないかもしれない」を、鑑定の巻物の使い道にする。
- `inventory` と `look` は、装備の特性・接辞の効果を文章で出す。

## 5. 発見

### 5.1 特殊部屋（prefab ＋ 地物）

すべてデータと既存のレジストリで足す。見つけると発見の点（§2.2）が入る。

| 部屋 | 中身 | 選択 |
|---|---|---|
| 施錠された宝物庫 | 宝 2〜3。扉は鍵が要る。鍵はその階の敵 1 体が持つ（倒すと落とす） | 鍵持ちを探して倒すか、通り過ぎるか。扉越しに中が見える格子扉にして、**報酬が先に見える**ようにする |
| 碑文の間 | 碑文 1〜2（`interact` で読む）。断章と、手がかり 1 つ（守護者の弱点／この階の宝物庫の位置／未鑑定の外見 1 つの正体のいずれか） | 寄り道の価値が分かりやすい |
| 賭けの祭壇 | `interact` で公開の表から 1 つ起きる（最大 HP +3／所持品 1 つに良い接辞／全鑑定／呪い／敵を呼ぶ／HP 半減）。表と確率は `look` で読める | 純粋な賭け。確率が見えるので期待値で判断できる |
| 番兵の詰所 | 眠っている敵 4 体と宝 1 つ | 忍び寄るか、起こさず抜けるか、見送るか |
| 先行者の野営跡 | 消耗品 2〜3 と書き置き（断章） | 小さな嬉しさ。浅い階の出現率を高くする |
| 崩れた書庫 | 巻物 2〜3。棚の間に潜む者 | 狭い通路の戦い |

- 新しい地物: `inscription`（碑文）、`gamble_altar`（賭けの祭壇）、`ward_fire`（護りの火）、`locked_door`＋アイテム `key`、`lever`（離れた扉・格子を開閉）。
- 既存の祭壇は「全鑑定」に加えて「呪いを解く」を持つ。

### 5.2 バイオームごとの仕掛け

各バイオームに、戦い方が変わる規則を 1 つずつ持たせる（`biomes.rules` と地形の属性）。到着時に 1 行の描写で知らせ、規則は `get_rules` と `look` で読める。

| バイオーム | 規則 | 使い道 |
|---|---|---|
| 石の広間 | レバーと格子扉。閉じた格子は視線を通すが通れない | 追跡を切る。投擲だけ通す |
| 湿った洞窟 | 浅い水は移動の手番コスト 150、騒音が 2 倍遠くまで届く。脆い天井（地物）は近くで騒音が起きると崩れ、範囲にダメージを与えて瓦礫になる | 水場に誘って距離を取る。物を投げて天井を落とす |
| 苔むした遺跡 | 丈の高い草は視線を遮る（中にいる者は隣接しないと見えない）。胞子嚢（地物）は攻撃か投擲が当たると毒の雲を 3 手番残す | 草に隠れて不意打ち。胞子嚢を撃って敵を毒にする |

新しいバイオームを 1 つ足す（深度 6 以上）: **沈んだ書庫**。本棚（視線を遮り、押して動かせる）と、読むと効果のある残り頁（床のアイテム）。

### 5.3 階の異変

生成時に低確率（`balance.floorEvent.chancePct`、初期値 25%）で、その階に 1 つ「異変」を付ける（`floorEvents.json`、`events` ストリーム）。到着時に**感じ取れることだけ**を 1 行で伝える。中身は探って確かめる。

| 異変 | 到着時の文 | 中身 |
|---|---|---|
| 賞金首 | 「何か大きなものが歩き回っている」 | 名前付きの強敵が最初から徘徊。賞金と宝 |
| 深い眠り | 「この階は静まり返っている」 | 全員が眠っている。ただし 1 体起きると全員が起きる |
| 荒らされた跡 | 「先に誰かが通ったようだ」 | 敵が少なく、アイテムも少ない。野営跡が必ずある |
| 溢れた宝 | 「どこかで金属が光った」 | 床の宝が多い。徘徊の湧きも多い |
| 番人の巡回 | 「規則正しい足音が聞こえる」 | 決まった経路を回る強敵。経路を読めば避けられる |

異変は観測の `self.floor.event_text` にだけ出る（ID と中身は出さない）。

### 5.4 描写と手がかり

- **初見の描写**: モンスター・アイテム・地物・バイオームに `desc` を足す（1 文）。このランで初めて見たとき `changes` の `first_seen` に 1 回だけ出し、以後は `look` で読める。
- **未鑑定アイテムの手がかり**: 薬と巻物の定義に `clue`（感覚の特徴。2〜3 種で共有する。例:「泡立っている」＝回復・活力、「刺すような匂い」＝毒・加速）を持たせる。所持して 30 手番たつか、斥候なら拾った時点で分かる。`inventory` に出す。正体は分からないが候補が絞れ、仮説を立てて試す遊びになる。
- **名前付きの強敵**: 通常の出現に低確率で混ざる（既存の接辞 2 つ＋名前＋賞金＋確定ドロップ）。見えた時点で `role: 'elite'` と賞金額が分かる。

## 6. 振り返り

助言はしない。**自分のプレイを事実で振り返れる材料**を出す。集計はルールを含まない関数（`shared/expeditionStats`）が、そのプレイヤーが知覚したイベントだけから行う（見ていないものは数えない）。

### 6.1 遠征レポート

遠征の終了時（`expedition_ended` の `result` と、`extract`／死亡への応答）に付ける。キャンプでは `expedition` で読み直せる。

```ts
report: {
  payout: { parts, multiplier_pct, banked, lost }
  compare: { vs_previous?: {...差分}, personal_best?: string[] }   // 「確定点が自己最高」「被ダメージが最少」など事実の列挙
  combat: { dealt, taken, hits, misses, melee_kills, thrown_kills, ability_uses, crits }
  economy: { potions_used, scrolls_read, items_left_unidentified, treasures_banked }
  tempo: { turns, turns_resting, floors, turns_per_floor, tool_calls, macro_share_pct }
  moments: { seq, turn_no, kind: 'hp_min' | 'big_hit_taken' | 'near_death_escape' | 'guardian_fight' | 'level_up' | 'discovery', text }[]   // 最大 8 件
  feats?: string[]   // §7.4
}
```

- `moments` の例:「手番 142: HP が最低の 3/36 になった（ゴブリンの投石兵 2 体の射撃を受けていた）」。`seq` があるので、リプレイでその場面へ飛べる。
- 死亡時は `death`（倒した相手、直前 10 件の出来事、直近 20 手番の HP の推移）を加える。
- テキストは 12 行以内。JSON は全項目。

### 6.2 プレイ中

- `expedition` ツールが、進行中の遠征の `combat`・`tempo` の途中経過を返す。
- 新しい照会ツール `review {expedition?: number}`: 終了した遠征のレポートと `moments` を返す。

## 7. 積み上げ（ランをまたぐもの）

### 7.1 プロフィール

- ランをまたいで残る単位として**プロフィール**を足す。`new_run` に任意引数 `profile_token`。無ければ新しく作って返す。同じ AI（や人間）が次のランで渡せば、記録が引き継がれる。
- 保存先はサーバーの `profiles/<id>.json`。**World の外**にあり、PlayerView には入らない。専用の `ProfilePort`（読み取りのみ）から、MCP と人間向け UI の両方に同じものを出す。

### 7.2 記録と図鑑

照会ツール `records`（手番を消費しない。キャンプの観測にも要約を出す）:

- **記録**: ランの数、確定点の最高・平均、最深、達成した遠征の数、倒した大守護者、死因の内訳（上位 5）、直近 5 ランの一覧。
- **図鑑**: 種族（遭遇・撃破・判明した能力・体力の記録）、アイテム種（鑑定した回数）、遺物、守護者の型と弱点、読んだ断章、見つけた特殊部屋。**完成度を「32/61」の形で出す**。未発見の項目は数だけ分かる。
- 次の節目: 「次の節目: 地下5階の大守護者（未踏破）／図鑑 32/61／実績 7/30」。

### 7.3 継承（図鑑の知識を次のランへ）

- 図鑑で撃破数が `balance.legacy.minKills`（初期値 5）以上の種族は、次のランの開始時に**思い出として引き継ぐ**（能力と体力の記録）。「前回学んだことが今回効く」を、推定残り HP と脅威度に反映させる。
- 引き継ぐのは**種族の知識だけ**。未鑑定の外見（ランごとにシャッフル）、守護者の弱点、地図は引き継がない。能力値・装備・加護も引き継がない（強さは毎回ゼロから）。
- **決定論を守る経路**: 継承の内容は参加コマンド（`join`）の引数 `legacy` としてサーバーが添え、`commands.jsonl` に記録し、`player_joined` イベントの after 値で World に入る。再実行もリプレイもプロフィールのファイルを読まない。
- 比較の公平さのため、`new_run {legacy: false}` と、サーバー設定 `legacyPolicy: 'on' | 'off'` を用意する。記録には継承の有無を残し、表を分ける。

### 7.4 実績

- `feats.json` に条件をデータで書く（遠征レポートと要約の値に対する比較式）。遠征の終了時に判定し、プロフィールに残す。**強さには影響しない**（記録だけ）。
- 初期の 30 個ほど。例: 無傷で 1 階を抜ける／薬を使わずに守護者を倒す／宝を 5 つ以上持ち帰る／危険度 5 の遠征を達成する／3 つの遠征を連続で達成する／同じ死因で 3 回死ぬ（不名誉なものも入れる）。
- 未取得の実績は名前だけ見える（条件は取るまで伏せるものと、最初から見えるものを分ける）。

## 8. 他のプレイヤーの痕跡（任意・最後）

- **墓標**: 死んだキャラクターの記録（名前・レベル・死因・深度）を、同じコンテンツ版の他のランの同じ深度に、地物 `grave` として低確率で出す。`look` で読める。所持品のうち 1 つが残る。
- **刻み**: プレイヤーは `inscribe {phrase, word}` で、定型句と単語の組（「この先 ＿ に注意」×「射手」など、固定の語彙）を足元に残せる。他のランに低確率で現れる。
- **自由文は扱わない。** 他の AI が書いた文章を別の AI の観測に入れると、指示の注入の経路になる。墓標の文はサーバーが事実から作り、刻みは固定語彙の組み合わせだけにする。
- **決定論**: 出す痕跡はラン作成時にサーバーが選び、`run_started` の after 値に入れる。生成はそれだけを参照する。
- **週替わりの挑戦**: 共通シード・継承なし・痕跡なしのラン（`new_run {challenge: 'weekly'}`）と、その専用の表。公開運用を始めるときに実装する。

## 14. 見直し（V3-2 後の評価を受けて、2026-11-16）

入力: [feedback/AI_PLAYTEST_V3-2_warrior_2026-11-16.md](feedback/AI_PLAYTEST_V3-2_warrior_2026-11-16.md)、[feedback/AI_PLAYTEST_V3-2_scout_2026-11-16.md](feedback/AI_PLAYTEST_V3-2_scout_2026-11-16.md)。この節は §1・§2・§10・§11 を上書きする。食い違う場合はこの節が正。段階名は **V3-2R**。

### 14.0 受け止め

戦利品の行、extract の可否、投擲の流れ、体力の推理は 2 体とも高く評価した。枠は合っている。外れたのは次の 3 点で、どれも設計の誤りである。

| 誤り | 何が起きたか |
|---|---|
| 深追いの点を「着いた」ことに付けた | 着いた階段でそのまま帰れるので、危険を冒す前に報酬が確定できた。最初の深追いは賭けにならなかった |
| AI にとっての資源を見落とした | AI が実際に払っているのはツールの呼び出し回数。マクロが 1 歩で止まり、退却が 1 歩 1 回になると、「退く」「拾う」「探す」は損得以前に選べなくなる。斥候の死因はこれ |
| 選択の検証を bot の比だけに頼った | bot は呼び出し回数を気にせず、表示も読まない。方針ごとの中央値が揃っても、1 回ごとの判断が割れているとは言えない |

### 14.1 深追いを「踏破」に変える

- **深追いの点は、目標より深い階の下り階段に立ったときに入る**（その階を横切り終えた時点）。階に着いただけでは入らない。
- 着いた階段ですぐ帰る道は残す（逃げ道であって、報酬ではない）。帰還できる場所は従来どおり、どの階段の上でもよい。
- これで判断は毎回「この階を横切る危険」と「横切った先の点」の比較になる。階段から離れるほど引き返しにくくなる。
- 観測の `next_overreach` は `{ depth, points, at: 'stairs_down', path_len: number | null }` とし、文章は「地下4階の下り階段に着けば +1000（未発見）」。下り階段が既知なら経路長を出す。
- **目的が深追いに埋もれないようにする。** 係数は「目的の基礎点 ≥ 踏破 2 階分」を満たす範囲で調整する（評価では目的 1600 に対して深追い 4500 だった）。
- **次の遠征への影響を出す。** 候補の目標深度は生成済みの最深階が基準なので、潜るほど次が深くなる。これを `expedition.haul.next_camp: { min_target_depth, recommended_level }` として毎回出す（「この階で帰ると、次の候補は地下7階以上・推奨 Lv5」）。新しい階を生成した時点で値が変わり、`changes` に出る。
- 撤退の「部分的な確定」のような中間の選択肢は足さない（踏破ごとに階段の上で帰れるので、区切りは既にある）。

### 14.2 呼び出しを資源として設計する

原則を一つ足す: **1 回の呼び出しは、必ず 1 つの判断に対応させる。判断の要らない反復に呼び出しを使わせない。0 歩で終わる呼び出しを作らない。**

**移動マクロの慎重さ**（`explore`・`travel_to`・`collect` の引数 `mode`。AI・人間とも同じ Command）:

| mode | 止まる条件 | 用途 |
|---|---|---|
| `careful`（既定） | 下の「既定の停止条件」 | 通常の探索 |
| `steady` | 追跡中（逃走中を除く）の敵が隣接した／進路をふさいだ／HP が `hp_floor` を下回った／初見の種族が見えた | 弱い射撃や毒を受けながら進む |
| `flee` | 到着／進路をふさがれた／HP が `hp_floor` を下回った。**隣に敵がいても動く** | 退却。途中で受けた攻撃は結果にすべて出る |

- `hp_floor` は引数（既定: `steady` は最大 HP の 50%、`flee` は 25%）。
- どの mode も 1 歩ずつ通常の `move` として記録する。敵は通常どおり攻撃してくる（退却の代償）。
- 実行前に 1 歩も進めないと分かる場合は、手番を使わずに理由付きで拒否する（`hostile_adjacent` など）。`valid_actions` には、その場で進める mode だけを出す（隣に敵がいれば `travel_to stairs_up mode:flee`）。

**既定の停止条件（`careful`）の手直し:**

- 止まる: 初見の**種族**、追跡中（逃走中を除く）で自分に届く敵の出現、視界内の敵が追跡中に変わった、攻撃された、HP が 50%・25% をまたいだ。
- 止まらない: 既知の種族の眠っている・気づいていない個体（`changes` には出す）、動かない敵で射程外のもの、毒などの継続ダメージ（HP のしきい値をまたぐまで）、アイテムの発見（`changes` には出す）。
- 動かない敵（`stationary`）は、隣接していなければ休憩も妨げない。

**拾う:**

- `explore`・`travel_to` に `pickup: true`（既定は `explore` が true、`travel_to` は目的地がアイテムのとき true）。通り道と目的地のアイテムを拾う（通常の `pickup` として 1 手番。満杯・鑑定済みの有害品は拾わない）。
- `collect` を一般化する: `collect {what: 'thrown' | 'items'}`。`items` は視界内と記憶のアイテムを近い順に回る。

**戦う:**

- マクロ `fight {target, hp_floor?}` を足す。隣接した対象に近接攻撃を繰り返す。止まる条件: 対象が倒れた／離れた、HP が `hp_floor`（既定 50%）を下回った、追跡中の別の敵が現れた、状態異常を受けた、敵が予備動作（§3.1）を見せた。結果は与えた・受けたダメージの合計と回数。
- 斥候は 1 体のオークに 17 回の呼び出しを使った。判断は「戦い続けるか」の 1 つなので、1 回で済むようにする。

**探す（地図の巻物と遺物）:**

- 知識に「自分の目で見たセル」（`knowledge.floors[].sighted`）を足し、「地形を知っている」（`seen`）と分ける。地図の巻物は `seen` だけを埋める。
- `explore` の行き先と「未探索」の表示は `sighted` で決める。巻物で地形が分かった階は「地形は判明・未見の区画あり」となり、`explore` は近道で未見の区画を回る。
- 遺物と守護者には**気配**を付ける。目標階にいる間、`expedition.sense: { dir: Dir, range: 'far' | 'near' }`（8 方向と、10 マス以内かどうか）を出す。engine が知識に書く公開ルール。正確な位置は見るまで出さない。

**応答の整理:**

- 記憶のアイテムは近い順に 3 件まで。残りは「記憶しているアイテム N 件（get_map）」の 1 行。戦闘中（追跡中の敵が視界にいる間）は 0 件にする。
- `valid_actions` の投擲は品目と対象をまとめる（`throw_item g|i -> e_a, e_b`）。
- 遠征の 2 行を 1 行にまとめる。「結果:」と「直前の出来事」が同じ内容のときは片方だけ出す。休めないときは休憩の見積もりを出さない。

### 14.3 判断に要る数字を見せる

- **自分の武器と投擲物の性能は隠さない。** 所持品と `self.attack` に、ダイス・命中の修正・射程を出す（「投げ槍 x2（投擲 1d8+1・射程 6・命中 +0）」）。鑑定済みの自分の持ち物は、定義の値をそのまま見せてよい。
- **射程**: `visible.monsters[].shot` に `out_of_range` を足す（品目ごとに違うので `shots: { slot, state }[]`）。ID を狙った射程外の投擲は `out_of_range`（既存コード）で拒否し、手番も品物も失わせない。座標を狙う投擲だけが手前に落ちる。
- **初見の敵の脅威は「不明」と出す。** 思い出に被ダメージの記録が無い種族は `threat: null`（「脅威: 不明（初見）」）。深度からの推定で 1〜2 と出すのをやめる。
- **会心の一撃を読めるようにする（ルール変更）。** 会心は「ダメージダイスが最大値になり、装甲を無視する」に変える（現行は「ダイス 2 倍から装甲を引く」）。
  - 最悪の一撃が「通常の最大値と同じ出目」に収まり、一度見た最大ダメージがそのまま上限の目安になる。オークの会心 15 のような、倍になって即死する跳ね方が無くなる。
  - 装甲の厚い敵にも会心が通る（斥候の短剣の会心がオークに 1〜2 しか入らなかった問題）。
- 視界内の敵に `worst_hit`（その種族から受けた最大ダメージの記録。会心を見ていれば会心の値）を出し、`alerts` に `lethal_range`（自分の HP が、視界内の追跡中の敵の `worst_hit` 以下）を足す。記録が無い敵は「一撃の大きさは不明」。
- **推定残り HP の言い方を変える。** 記録は標本であって種族の範囲ではない。文章は「記録どおりなら残り 6〜8（記録 3 体: 体力 8〜8）」とし、上限を使うのは 5 体以上（`minSamples` 3→5）。

### 14.4 キャンプと候補

- **危険度の頭打ちをやめる。** 危険度を段階ではなく差で出す: `level_gap = 推奨レベル(目標深度) − 自分のレベル`、`trait_danger` は別に出す（「推奨 Lv6・あなた Lv2（差 +4）／条件 +1」）。5 段階の数字は廃止する。
- **3 枠の目標深度を重ねない。** 堅実 = 最深 +1、標準 = +2、野心 = +3〜4。目的の種類も、可能な限り 3 枠で別にする。
- **推奨レベルは実測から決める。** 式ではなく、bot がその深度に着いたときのレベルの中央値を表（`balance.expedition.recommendedLevelByDepth`）にし、表より深い階は外挿する。
- **最初の遠征も選ばせる。** `new_run` は `objective` を省くと**キャンプから始まる**（候補 3 つ、`awaiting: 'camp_choice'`）。`objective` を渡せば従来どおり直接始まる。最初の候補は浅くする（堅実 = 地下2階、標準・野心 = 地下3階）。
- 150 回の呼び出しで、最初の遠征の帰還と 2 回目の候補選びまで届くことを目安にする（§14.6）。

### 14.5 成長と装備

- **成長を深度に合わせる。** 経験値の出どころに「新しい階への到達」と「遠征の達成」を足す（`balance.xp.perNewDepth`・`perObjective`）。敵を避けて進んでも、深度相応に育つ。目安は「貪欲 bot が深度 d に着いたときのレベルの中央値が、推奨レベル(d) の ±1」。評価では Lv2 で地下7階（推奨 Lv6）だった。
- レベルアップの応答に、上がった能力値を並べる（V3-4 の特技の選択が入るまでの間も）。
- **装備に痛みを付ける（V3-4 に追加）。** 重い鎧（鱗鎧・板金鎧）は移動の手番コストが増え、眠っている敵が起きやすくなる。「見つけたら着る」の一択をやめる。
- 回復の薬が余っている（斥候は地下4階までに 7 本、死亡時に 4 本残り）。薬の出現の重みを下げ、「死亡・帰還時に残った回復の薬の数」を計測に足す。

### 14.6 計測の見直し（§10 を置き換える）

bot の方針比較は残すが、**合格の根拠にしない**。次の 3 層で確かめる。

**1. 1 回ごとの判断（bot）**

| 測るもの | 目安 |
|---|---|
| 踏破 1 階あたりの死亡率（達成後に次の階を横切り始めてから、下り階段に着くまで） | 最初の 1 階で 8% 以上。階を重ねるごとに上がる |
| 踏破の期待値 ÷ 即帰還の期待値（その時点の戦利品を賭け金として） | 0.9〜1.3。1.5 を超えたら「選ぶまでもない」と見なす |
| 深度 d 到着時のレベルの中央値 − 推奨レベル(d) | ±1 |

**2. 呼び出しの予算（bot。マクロを使う方針で、MCP の呼び出し回数を数える）**

| 測るもの | 目安 |
|---|---|
| 0 歩で終わったマクロの呼び出し | 0 |
| 5 歩未満で止まった移動マクロの割合 | 20% 以下 |
| 敵 1 体を倒すのに使った呼び出しの中央値 | 3 以下 |
| アイテム 1 個を拾うのに使った呼び出し | 平均 0.5 以下 |
| 最初の遠征を帰還まで終える呼び出しの中央値 | 60 以下 |

**3. AI プレイヤーの評価（合格の条件にする）**

V3-2R の後に、前回と同じ条件（ブラインド、戦士と斥候、各 150 回）で行う。報告の書式に次の問いを足す。

- 帰るか粘るかを判断した場面ごとに: 迷ったか、何を比べたか、足りなかった情報は何か。
- 退きたかったのに退けなかった場面はあったか。
- 呼び出しが無駄になったと感じた場面と、その回数。
- キャンプの 3 候補を、何を基準に選んだか。

合格の目安: 2 体とも 2 回目の候補選びまで届く。最初の踏破の判断を「計算するまでもない」と書く者がいない。「退けなかった」が死因に挙がらない。

§12 と §14.10 の確認事項はすべて決まった。1〜3 は依頼者から「AI プレイヤーの目線で、ゲーム体験として好ましいほうを選ぶ」と任された設計担当の判断。未確認の事項は無い。

| 3 | 継承（§7.3） | **既定で「あり」。** 引き継ぐのは種族の知識だけ |

| 6 | 会心の一撃のルール（§14.3） | **変える。**「ダイスが最大値になり、装甲を無視する」 |

### 16.1 判断の理由（1〜3）

- **会心**: 斥候の死は、HP 15 で「まだ一発は耐える」と読んだところへ会心 15 が来たものだった。読めない跳ね方で死ぬと、残るのは「運が悪かった」で、次のランで変える行動が無い。永久死のゲームで続けたくなるのは、死が自分の判断の結果だと分かるときである。新しい規則なら、一度見た最大の一撃がそのまま最悪の目安になる。こちらの会心も装甲を抜くので、短剣の会心が硬い敵に 1 しか入らない虚しさが消える。倍になる派手さは減るが、「通った」手応えは増える。
- **物語の枠**: 潜るたびに形を変える層と、持ち帰る記憶という枠は、このゲームの仕組み（自動生成、思い出、図鑑、継承）と同じ形をしている。物語が仕組みの説明になっているので、`thought` に書く言葉が「階段へ向かう」から「この欠片を持ち帰る」に変わる。2 体とも「なぜ潜るのかが無い」と書いた。
- **継承**: ランが終わるとキャラクターは消える。そのとき何も残らなければ、次のランは同じ 1 階のやり直しでしかない。強さは持ち越さず、学んだことだけが残る形なら、死んでも無駄にならず、次のランの序盤が「知っている相手を、前より上手く捌く」時間になる。比較が要るときのために `legacy: false` は残す。

### 16.2 枠の使い方（§3.4 の補足）

- 文章は短く、説明しすぎない。ブリーフィングは 1 文、初見の描写は 1 文、断章は 2〜3 文まで。応答の量を増やさない（初見のときと `look` でだけ出す）。
- 固有名詞は最小限にする。都にも坑にも名前は付けず、「記録庫」「番人」「欠片」「潜る者」の普通名詞で通す。守護者と遺物だけが名前を持つ。
- 物語は判断を指示しない。断章が伝えるのは事実と手がかりだけ（§0.2 の方針 1）。
- 継承した知識は、文章の上では「前の潜る者が残した覚え書き」として現れる（`recall` に「覚え書きより」と添える）。自分で確かめた記録と区別できるようにする。

### 16.3 プロフィール（§7.1 の確定）

MetaMuse はファイルにトークンを保存でき、VM の再起動後も残ることを確認した。一方、現行の `player_token` はランごとの発行で、ランをまたぐ識別子は無い。そこで次のとおりにする。

- **`profile_token` は `player_token` と別のもの**にする。プロフィールはランの外にあり、サーバーが `profiles/<id>.json` に持つ。
- `new_run`・`join_run` に任意引数 `profile_token`。省くと新しいプロフィールを作り、結果に `profile_token` と `profile_id` を返す。次のランで同じトークンを渡せば、同じプロフィールに記録が積まれる。
- 新しいツール `profile`（引数 `profile_token`、ランに束縛されていなくても呼べる）: 表示名、記録の要約、進行中・再開できるラン（`run_id` のみ。`player_token` は返さない）。
- プロフィールは表示名を持つ（最初のキャラクター名。変更可）。記録の一覧では、キャラクター名とプロフィール名の両方を出す。
- `profile_token` は記録を書き足す権限なので、`player_token` と同じ扱いにする（観戦・HTTP・ログには出さない。`commands.jsonl` にはプロフィールの ID だけを残す）。
- README の接続手順に「`profile_token` を保存し、次の `new_run` で渡す」を足す。
- ホスト駆動（`npm run drive`）は `--profile-token` を受け取り、ランが終わったら同じプロフィールで次のランを始められるようにする（`--continue`）。

## 17. 実装メモ（V3-2R、2026-11-16）

確定した設計は DESIGN.md §15、プロトコルは PROTOCOL.md に反映した。§14 との差分と、実装で決めたこと:

- **§14.6 の目安のうち 2 つが未達**（DESIGN.md §15.6）: 踏破 1 階目の死亡率は bot で 0%（目安 8% 以上）、最初の遠征の呼び出しは中央値 65（目安 60 以下）。前者は湧き間隔・経験値を動かしても変わらなかった（bot は全快してから踏破し、`fight` で一対一を処理する）。§14.6 の 3（AI プレイヤーの評価）で、最初の踏破を「計算するまでもない」と書く者がいないかを確かめる。
- **5 歩未満の移動マクロ**: 敵へ近づく `travel_to <敵>` は短いのが自然なので割合から外し、別に数えた。
- **careful の停止**: 列挙に無い「階段の発見」は explore で止まる条件として残した（踏破の判断の起点になるため）。アイテムの発見では止まらない。
- **explore の拾得**: 「通り道と目的地」に加えて、見えている・記憶した拾える品の位置も行き先に含めた（アイテム 1 個あたりの呼び出しを 0.5 以下にするため）。遺物は自動では拾わない（拾うと階が起きる）。
- **fight**: 設計どおり隣接が条件。予備動作での停止は V3-3（§3.1）で足す。
- **動かない敵**: 公開の種族タグ `stationary` で判定（隣接していなければ careful の停止・休息の妨げにならない）。
- **気配の距離**: チェビシェフ距離 10 以内を near。
- **鑑定の既定**: スロット順で最初の未鑑定品（使った巻物の種類を除く。乱数を使わない）。
- **推奨レベルの表**: bot の計測の中央値（深度 1〜8）。深度 9 以降は直近 4 階の傾きで外挿。
- **ターンフィード**: キャンプから始まったランの最初の候補選びは `turn` として送る（`ended` だと外部のホストが止まるため）。

## 18. 見直し 2（V3-2R 後の評価を受けて、2026-11-16。V3-2R2）

§17.1 の 6 点への設計判断。**次に実装するのはこの節（V3-2R2）**で、§14 のうち §14.1 の点の式・§14.3 の候補の式・§14.6 の目安の一部を上書きする。規模は V3-2R より小さい。乱数の使い方と点の式が変わるので `engineVersion` を上げる。

### 18.0 受け止め

V3-2 は「進むのが無条件に得」、V3-2R は「帰るのが無条件に得」になった。係数の大小ではなく、次の 3 つの構造が原因である。

- **負けの段階が 2 つしかない。** 帰還（100%）の下が、撤退（階段まで歩けたとき）と死（ランの終わり）だけで、階段から遠い場所には「死」しかない。戦士は「戦利品を失うことより、ランが終わることが判断を支配した」と書いた。賭けの負けが大きすぎるので、賭けそのものが選ばれない。
- **踏破の点が定額で、賭け金（戦利品）に比例しない。** 目的の点が大きいほど踏破は割に合わなくなる。
- **粘る側の費用が読めない。** 下り階段の場所が分からないので、踏破にかかる手数を見積もれない。読めない費用は「高い」と見なされる。

候補の逆転（指摘 2）と群れの危険（指摘 4）は、これとは別の単純な誤りで、式と表示を直す。

### 18.1 退却（指摘 1）

1. **extract は、階段の上なら追跡中の敵が見えていてもできる。** `use_stairs` と同じ 1 手番の行動として扱う。
   - 理由: 敵は階段を追ってこない（実装で確認した）。今でも「階段を使う → 着いた階段で extract」の 2 回で同じことができ、禁止は呼び出しを 1 回増やして混乱させているだけだった。斥候が帰路で 2 戦を挟んだのはこのため。
   - 退却の費用は「階段まで行くこと」で払う。get_rules に「階を移れば敵は追ってこない」を明記する。
2. **帰還の綱（新しい品 `core:lifeline`）。** 階段から遠い場所での退却手段。
   - 遠征の開始時に、キャンプが参加者それぞれの所持数を 1 本にそろえる（余っていても 1 本、無ければ補充）。坑の中では手に入らない。捨てる・投げる・渡すはできない。
   - 使うと `balance.lifeline.turns`（初期値 2）手番のあいだ行動できず、その後キャンプへ戻る。1 回の呼び出しで最後まで進む（途中で止まるのは死んだときだけ）。その間の被害は受ける。
   - 確定するのは **戦利品全体の `balance.lifeline.pct`（初期値 50）%**。目的を達成済みならその点も 50% で入る（持っている遺物は納めた扱い）。未達成なら撤退と同じ額になる。
   - 結果の段階は 4 つになる: 階段で帰還 100% ／ 綱で帰還 50% ／ 階段で撤退 50%（目的なし） ／ 死 0 とランの終わり。
   - 遠征の行に `if_lifeline_now` を出し、valid_actions に「use_item（帰還の綱: 2 手番かかる。今の群れの被害見込み …）」を出す。遠征の結果の理由に `lifeline` を足す。
   - 即時にしない理由: 即時だと「HP が 1 になったら引く」だけの操作になり、判断が要らない。2 手番かかれば「まだ耐えられるうちに引く」判断になり、§18.2 の被害見込みと組で計算できる。
3. **転移の巻物は逃げ道として働くようにする。** 着地点は「元の位置からチェビシェフ距離 `balance.teleport.minDistance`（初期値 12）以上、かつ追跡中の敵から見えないマス」から選ぶ。無ければ距離の条件だけ、それも無ければ今までどおり。敵が転移する場合も同じ規則（敵・プレイヤーを区別しない）。乱数は今までどおり `runtime`。
4. **逃げ道の見込みを出す。** 追跡中の敵が見えていて既知の階段があるとき、`alerts` に `escape { stairs, path_len, faster }` を出す（`faster` は自分より速い追跡中の敵の数）。文は「上り階段まで 12 歩。追ってくる敵のうち 4 体はあなたより速い」。

### 18.2 危険を読めるようにする（指摘 4）

見た目で分かることは最初から出し、数値は記録から出す、という線引きに改める。

- **見れば分かる特徴は初見から出す**（`visible.monsters[].traits`）: 速さの 3 段階（遅い・普通・速い。自分の今の速さとの比較）、群れる（`pack`）、飛び道具を持つ（`ranged`）、動かない（`stationary`）。種族の公開タグから作る。体力・威力・回避・弱点は今までどおり伏せる。
- **群れ全体の被害見込み**（`alerts.incoming`）: 追跡中で見えている敵について、種族ごとの `worst_hit` の合計と、記録のない個体の数。文は「追跡中 6 体。記録の最大被害の合計 14／手、ほかに記録のない 2 体。あなたの HP 30」。思い出だけから観測が計算する。`lethal_range` はこの合計でも判定する。
- **命中の記録**: 思い出に種族ごとの「自分の攻撃の回数と命中」「相手の攻撃の回数と命中」を足し、`visible.monsters[]` に「あなたの命中 1/6・相手の命中 3/5」を出す（近接と投擲は分ける。記録が無ければ出さない）。確率そのものは出さない（相手の回避は伏せた情報）。
- **文言**: 被弾の記録が無いだけの種族は「脅威: 不明（被弾の記録なし）」。「初見」は本当に初めて見た種族だけ。
- **浅い階の群れ**: 群れの数の上限を `min(種族の上限, 深度 + 1)` にする（地下1階は 2、地下2階は 3）。推奨レベルどおりで来た者が、見て避ける間もなく囲まれるのを防ぐ。

### 18.3 キャンプの候補（指摘 2。§14.3 の式を上書き）

- **点の式を「枠の基礎点 × 種類の係数 × 深さの係数」に変える。** `points`（種類ごとの基礎点）・`pointsPct`・`pointsPerExtraDepth` は廃止。
  - 枠の基礎点 `slots.*.base`: 堅実 1600・標準 2400・野心 3600。
  - 種類の係数 `typePct`: 到達 100・守護者 120・遺物 120・守護者付きの遺物 135。
  - 深さの係数: `100 + 5 × 目標深度` %。
  - これで、どの組み合わせでも 堅実 < 標準 < 野心 になる（堅実の最大 1600 × 1.35 = 2160 < 標準の最小 2400、標準の最大 3240 < 野心の最小 3600）。種類は枠の中の揺れにとどまる。
- **野心は +3 固定**（+4 をやめる）。
- **推奨レベルの表は、隣り合う階の差が 1 以下になるように丸める**（今の `[1,2,2,4,…]` は 2→4 の段差で、標準の差が野心並みに出る）。
- 条件（traits）の倍率は今までどおり確定時にかかる。
- 最初の遠征（標準と野心が同じ地下3階）は、条件と種類で差が付くのでそのまま。

### 18.4 踏破（指摘 3 と 5 の後半。§14.1 の点の式を上書き）

- **踏破の点を目的の点に比例させる。** n 階目の点 = `目的の点 × (25 + 10 × (n − 1))%`、下限は今の `600 + 300 × (n − 1)`。目的の点は条件の倍率をかける前の値。2 階分で 60% なので「目的が主、踏破が従」は保たれる。`overreachFirst`・`overreachStep` は下限として残す。
- **下への風**（`floor.draft { dir }`）: 今いる階の下り階段をまだ見ていないとき、その 8 方向だけを出す（遠近は出さない）。文は「下への風: 南東」。
  - 遺物・守護者の気配は 2 体とも「探索が推理になった」と評価した。同じ形を階段に使う。寄り道するか直行するかの選択は残る。
  - 知識は engine が計算して `knowledge_updated` で書く（気配と同じ経路）。
- **探索の進み具合**（`floor.explored`）: その階の通れるマスのうち見た割合を 4 段階（およそ 1/4・半分・3/4・ほぼ全て）で出す。
- **`next_overreach` に `dir` を足す**（`path_len` が出せないとき）。**`next_camp` は 2 通り出す**: 今帰った場合と、次の踏破をした場合。
- §18.1 の綱で、踏破の負けは「死」から「半分」に変わる。点の式とあわせて、帰る・粘るの期待値が近づく。

### 18.5 呼び出し（指摘 5 の前半）

- **`fight` を「その相手と決着を付ける」マクロに広げる。**
  - `fight { target, with?: slot, hp_floor? }`。`with` に投げる品のスロットを指定すると投擲で戦う。
  - 相手が追跡中で届かない間は待つ（近接は隣に来るまで、投擲は射程と射線が通るまで。最大 10 手番）。戦士の「迎え撃つための wait」と斥候の「射程待ちの wait」がなくなる。眠っている・気付いていない相手には今までどおり `travel_to` か単発の投擲。
  - 当てて逃げる相手: 隣から離れても、追跡中で 2 マス以内にいる間は 2 手番まで待つ（追わない）。
  - 投擲の停止条件: 相手が倒れた／相手が隣に来た（`with` のときだけ。続けるなら呼び直す）／その品が尽きた／射線が 3 手番続けて通らない／相手が逃げて射程を出た／新しい追跡中の敵／`hp_floor`。
- **`wait { turns }`**（最大 10）: 何か変化があれば止まる（敵が見えた・隣に来た・被害）。
- **steady も、その階の下り階段を初めて見たときは止まる**（flee は止まらない）。踏破の判断の起点なので。
- **経路は、既知の動かない敵の隣を罠と同じ扱いで避ける**（ほかに道が無ければ通る）。
- **rest は、すでに報告した逃走中の個体が視界を出入りしても止まらない。**
- **自分が投げた品は「見えるもの」で 1 行にまとめる**（本数と最寄りの位置）。
- **valid_actions の steady・fight に、既定の `hp_floor` の実数を出す**（「HP 24 未満で止まる」）。

### 18.6 守護者（指摘 6 のうち今直すもの）

本体は V3-3 のまま。次の 2 点だけ先に直す（「体力 12 の守護者大ネズミ」を出さない）。

- 守護者にする種族は、その深度の候補のうち経験値が上位半分のものから選ぶ。`vermin` タグは除く。
- 守護者の体力の下限 `guardian.minHp`: `16 + 4 × 深度`。
- 守護者を倒した文は、ほかの変化と別の行にして先頭に出す。

成長・ビルドは V3-4、名前・予備動作・遺物の違いは V3-3、自己ベストと節目は V3-6 で扱う（評価の上位にどちらも挙がっているので、V3-2R2 の後は予定どおり V3-4 から）。

### 18.7 確かめること（不変条件）

- **視界外の相手への毒**: 毒を与えた者を `source` にしたので、相手が視界外にいても `damaged` が毒を与えた者に届く経路ができた。視界外にいる間は、相手の名前・体力・位置を出さない（斥候の報告 6 章 7）。倒れたときだけ「あなたの毒で何かが倒れた」と、撃破・賞金・経験値の変化を出す（自分の行動の結果なので知らせる）。テストを足す。
- 下への風・探索の進み具合・逃げ道の見込みは、どれも `projectPlayerView` を通し、未探索の地形そのものは渡さない。

### 18.8 計測と合格の目安（§14.6 の一部を上書き）

- 「踏破 1 階目の死亡率 8% 以上」は取り下げる（bot は全快してから進むので動かせず、綱を入れると意味も変わる）。代わりに **踏破 1 階目が「綱か死」で終わる率 10〜25%**。
- 踏破の期待値 ÷ 即帰還の期待値 0.9〜1.3 は据え置き（綱の 50% を含めて計算する）。
- **枠ごとの達成率**（推奨レベルどおりの bot）: 堅実 90% 以上・標準 60〜85%・野心 30〜60%。外れたら枠の基礎点ではなく、条件の数と推奨レベルの表で合わせる。
- 最初の遠征の呼び出し 60 以下は据え置き（`fight` の拡張で下がる見込み）。投擲が呼び出しに占める割合（斥候の bot）30% 以下を足す。
- **AI プレイヤーの評価**（同じ条件でもう 1 回）:
  1. 「退けなかった」が死因に挙がらない。
  2. 候補選びで「迷う余地がない」と書く者がいない。
  3. 帰るか粘るかで、2 体の判断が毎回同じ向きにそろわない（踏破を 1 回以上実行する者がいる、または綱を使う判断が記録される）。

順序: **V3-2R2（この節）→ AI 評価 → V3-4 → V3-3 → V3-5 → V3-6 → V3-7**。

### 18.9 実装担当の判断でよいこと

係数の初期値（綱の手番と割合、転移の距離、枠の基礎点、踏破の割合、守護者の体力）は計測で動かしてよい。ただし §18.3 の「どの組み合わせでも 堅実 < 標準 < 野心」と、§18.1 の「結果の段階が 4 つ」は崩さない。依頼者への確認事項は無い。

## 19. 実装メモ（V3-2R2、2026-11-16）

確定した設計は DESIGN.md §16、プロトコルは PROTOCOL.md に反映した。§18 との差分と、実装で決めたこと:

- **帰還の綱の進み方**: 状態 `core:recall`（行動不能）として実装した。プレイヤーの手番の開始で行動不能なら自動で手番が終わる既存の仕組みに乗るので、`use_item` の 1 回の step の中で最後（キャンプ）まで進む。COOP で同じ階に他のプレイヤーがいれば、その人の手番を挟んで進む。
- **綱の確定と記録**: 目的を達成済みで綱を使っても、遠征の終了理由は `lifeline` で、「達成した遠征」の数には入れない（戦利品 × 50% は確定する。持っていた遺物は納める）。
- **綱の所持数**: 手放せない品（`bound`）は所持数に数えない（`inventory_count`・拾える判定・`inventory_full`）。キャンプが持たせるのは遠征の開始時（`item_issued`）。最初の遠征を `new_run { objective }` で直接始める場合も同じ。
- **転移の「見えない」**: プレイヤーの転移では追跡中の敵の視界（半径と射線）、敵の転移ではプレイヤーの今の視界。候補は全セルを走査して作り、`runtime` で 1 回だけ引く（旧来の試行の繰り返しをやめた）。
- **群れの被害見込み**: 対象は「自分に届く追跡中の敵（逃走中を除く。動かない敵は隣にいるときだけ）」。1 体のときは従来の `enemy_in_view` / `enemy_adjacent` のままにし、2 体以上で `incoming`（`multiple_enemies` を置き換え）。
- **速さ**: `EntityView` にモンスターの素の速さを足し、観測が状態異常の倍率をかけて自分の実効の速さと比べる（3 段階しか出さない）。
- **初見**: 「本当に初めて見た種族」は、撃破が無く、遭遇した個体の数がいま見えている数以下の種族とした（同時に見えた群れも初見）。
- **下への風**: 今いる階の下り階段を 1 つも見ていない間だけ。複数あれば最寄り（チェビシェフ距離）。探索の進み具合は「通れるマス（扉を含む）のうち自分の目で見た割合」を 40・65・90% で区切る（地図の巻物だけで知ったセルは数えない）。
- **fight の待ち**: 開始時に待つことになる相手が眠っている・気付いていないときは手番を使わずに拒否する（`target_not_hunting`）。動かない相手を待つ場合も拒否（`target_not_approaching`）。投擲は ID 指定の `throw` を出すので、射程外・射線なしの拒否は起きない（観測で判定してから投げる）。
- **steady の停止**: careful の移動マクロも、その階の下り階段を初めて見たら止まるようにした（explore 以外の careful も含む。踏破の判断の起点）。
- **視界外の毒**: 毒の `damaged` は射影で落とし、`died` は種族・接辞も伏せる。撃破・賞金・経験値は入るが、種族を知らないので思い出の撃破数と「初めて倒した種族」の発見には数えない。
- **守護者**: 候補は生成表のタグに合い、その深度の重みが正の種族。`vermin` と、動かない・逃げ回る行動様式を除き、経験値の降順で上位半分（切り上げ）から選ぶ。
- **bot**: 投擲は `fight { with }`（3 マス以上離れた相手）、HP 30% 未満で群れ（2 体以上）か `lethal_range` なら、階段の上では extract、遠ければ綱を使う。
- **計測（§18.8。DESIGN.md §16.6）**: 綱か死の率・期待値の比・野心の達成率・呼び出しの予算・斥候の投擲の割合は目安の範囲（綱か死の率は 7.7〜18.2% と回数の少なさで揺れる）。**堅実（74〜78%）と標準（38〜43%）の達成率が未達**。
  - 不足はほとんどが守護者と遺物の目的で、死因の多くは守護者戦（射撃して距離を取るゴブリンの投石兵と、経験値の上位半分から選ぶ守護者）。
  - §18.8 の手段（条件の数・推奨レベルの表）は効かなかった。条件の数を減らしても達成率は変わらず、推奨レベルの表は bot の強さを変えない（推奨に届いた枠だけを選ぶ bot では、標準と野心がほとんど選ばれない）。
  - §18.9 の範囲で守護者の体力を下げた（下限 10 + 3 × 深度、接辞の体力 +100%）。これ以上は守護者の特別感と衝突するので、設計の判断に回す（例: 守護者の種族から射撃型を外す・達成率の目安を目的の種類ごとにする・V3-3 の守護者の型で戦い方を読めるようにする）。

評価で見つかった実装の不具合（直した。DESIGN.md §16.7）: 投擲と敵の射撃で射線が非対称（敵は撃てるのにこちらは「射線:通らない」）／隣の敵に投擲の fight を勧める／travel_to の目的地にした有害品を拾わない／休憩の見積もりが毒を数えない／撤退の結果の文に掛かっていない倍率が出る／同じアイテムの「見つけた」の繰り返し／一度見た個体が後の遠征で「新たな敵」になる／「踏破してから」の次の候補の文（実際は降りた時点で深くなる）／レベルアップの最大 HP 増分が「回復」と出る／blocked の文（「次のマス」）／ルールの new_run の既定の矛盾／逃走中の敵に「あなたを攻撃中」／守護者が命中の記録に混ざる／綱の説明が毎回出る。

設計の判断が要る指摘（未対応。上位のもの）:

1. **目的の種類が危険を決める**: 到達は着いた階段で帰れるので安全で得。種類の係数（到達 100・守護者 120・遺物 120・守護者付きの遺物 135）では釣り合わず、堅実に守護者付きの遺物が来ると標準の到達より重い（2 体とも指摘。bot の枠の達成率の不足もこれが主因）。
2. **推奨レベルとの差が開き続ける**: 3 回の遠征で、堅実でも差 +2、ほかは +3〜+4（2 体とも上位）。次の候補の深さに成長が追いつかない。
3. **綱が使われない**: 隣に強敵がいると 2 手番は長すぎ、離れていれば歩くか転移で足りる。速い敵から退けない場面は残った（戦士）。
4. **危険が戦う前に読めない**: 守護者の格・相手の装甲・初見の強敵（トロルは「遅い」としか分からない）。
5. **戦う・探す理由**: 撃破 +10・宝 60 程度に対して目的が 3000 点台で、階段へ直行するのが最適。
6. 成長・ビルドの選択（V3-4）、長期目標・記録・物語（V3-3・V3-6）は 2 体とも上位に挙げた。
