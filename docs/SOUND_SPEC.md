# MuseDungeon 音の仕様

[ASSET_SPEC.md](ASSET_SPEC.md) の音の版。状況に連動して変わる音楽（パート・音階・オクターブが変わる、MIDI 風の音）の**技術仕様**を定める。
旋律・和声・音色・曲想は本書では決めない。本書の目的は、音を別の担当（以下「音の担当」）が制作し、コードを変えずに差し込めるようにすることである。

経緯は [IDEAS.md](IDEAS.md) §1。音は**演出だけの層**であり、情報を運ばない（2026-11-18 に依頼者と決定）。

鳴らす仕組みと音の状態を作る関数は実装済み（2026-11-18）。定義の形（版 1）・鳴らし方・音の状態の読み方は §12。

---

## 1. 基本方針

1. **音が無くてもゲームは動く。** 既定は無音。音のテーマが無い・読めない・ブラウザが音を出せないとき、何も起きない。
2. **音は情報を運ばない。** 音を動かす入力は、その人間の画面にすでに出ている情報だけである（§2）。音を聞ける人だけが得をすることがあってはならない。
3. **AI のプレイヤーには何も渡さない。** MCP・HTTP・WS の中身は変えない。エンジンも World も変えない。
4. **同じ状況なら同じ音。** 音の状態（§2）は、プレイヤーの視界のデータから決まる純粋な関数で作る。リプレイと観戦でも同じ音になる。
5. **ゲーム側は音を知らない。** 音の状態から実際の音への対応は、クライアント側の**音のテーマ**（定義ファイル。§5）が持つ。画像のテーマと同じ考え方である。
6. **設計と作曲を分ける。** 「何に連動させるか」（§2・§3）は設計担当が決める。「どう鳴らすか」（§5 の中身）は音の担当が決める。

## 2. 入力: 音の状態（SoundState）

音を動かせるのは、次の値と、§2.2 の合図だけである。**ここに無いものを音に使ってはならない。** 足したいときは §9 の手順で求める。

### 2.1 続く状態

| 名前 | 値 | 決め方 |
|---|---|---|
| `scene` | `camp` / `explore` / `alert` / `combat` / `guardian` / `warden` / `ended` | 下の表。上から順に見て、最初に当てはまったもの |
| `threat` | 0〜3 | 見えている追跡中の敵の数。0 体＝0、1 体＝1、2〜3 体＝2、4 体以上＝3 |
| `hp` | `healthy` / `wounded` / `badly_wounded` / `near_death` | 自分の HP の帯（画面の表示と同じ区切り。`hpState`） |
| `depth_band` | 0〜3 | 今いる階の深さ。地下 1〜4 階＝0、5〜9 階＝1、10〜14 階＝2、15 階より深い＝3 |
| `depth_tier` | 0 以上の整数（上限なし） | 今いる階の深さを 5 で割った商（切り捨て）。地下 1〜4 階＝0、5〜9 階＝1、10〜14 階＝2、15〜19 階＝3、20〜24 階＝4…。地下 19 階までは `depth_band` と同じ値で、その先も増え続ける。巡らせたいとき（4 つごとに戻すなど）は、定義ファイルの側で余りを取る（書き方は §5 のとおり音の担当と実装担当が決める） |
| `biome` | バイオームの ID、または `none` | 今いる階のバイオーム。いまあるのは `core:stone_halls`（石の広間。地下 1 階から）・`core:damp_caves`（湿った洞窟。1 階から）・`core:overgrown_ruins`（苔むした遺跡。2 階から）・`core:sunken_archive`（沈んだ書庫。6 階から）の 4 つ。データで増えるので、知らない ID が来ても鳴るようにする |
| `floor_kind` | `standard` / `sanctuary` / `warden_hall` / `other` | 今いる階の種類 |
| `telegraph` | あり / なし | 見えている敵が予備動作（構え）を見せている |
| `sense` | `none` / `far` / `near` | 目標の気配。画面に気配が出ていないとき `none`。出ているとき、距離の表示が 8 マス以内なら `near`、それより遠ければ `far` |
| `stake` | 0〜2 | 持ち帰っていない戦利品の大きさ。0＝無い、1＝ある、2＝これまでの遠征 1 回の確定の最高を超えている |
| `ailment` | あり / なし | 自分に悪い状態（毒・朦朧など）が付いている |
| `boost` | あり / なし | 自分に良い状態（加速など）が付いている |

`scene` の決め方:

| 値 | 条件 |
|---|---|
| `ended` | ランが終わった（死亡・引退） |
| `camp` | キャンプにいる（遠征と遠征の間） |
| `warden` | 見えている敵に、生きている大守護者がいる |
| `guardian` | 見えている敵に、生きている守護者がいる |
| `combat` | 追跡中の敵が隣にいる。または、直前の 3 手番のうちに自分が攻撃したか攻撃された |
| `alert` | 追跡中の敵が見えている |
| `explore` | 上のどれでもない |

- キャンプにいる間（`scene` が `camp`）は、階にいないので、`depth_band` と `depth_tier` は 0、`biome` は `none`、`floor_kind` は `other` に固定する。キャンプは帰る場所なので、どこまで潜ったかで音を変えない。`ended` では、最後にいた階の値のままにする。
- 「見えている」は、画面に今描かれていることを言う。覚えているだけの敵、視界の外の敵、眠っているかどうか分からない敵の内部の状態は使わない。
- 協力プレイでは、各自の画面の状態から作る（人によって音が違ってよい）。
- 観戦とリプレイでは、**見ている相手のプレイヤーの視界**から作る。観戦者だけに見えている情報からは作らない。

### 2.2 一度きりの合図（キュー）

そのプレイヤーに届いた出来事から作る。短い音（スティンガー）を鳴らすためのもの。

| 名前 | 起きるとき |
|---|---|
| `hit_dealt` / `hit_taken` | 自分の攻撃が当たった／自分が被害を受けた |
| `miss` | 自分の攻撃が外れた |
| `crit_dealt` / `crit_taken` | 自分の攻撃が会心になった／自分が会心を受けた（`hit_dealt`・`hit_taken` の代わりに起きる。同じ一撃で両方は鳴らさない） |
| `kill` | 敵を倒した |
| `telegraph_start` | 見えている敵が構えた |
| `pickup` / `treasure` | 品を拾った／宝を拾った |
| `discovery` | 発見（特殊部屋・新しい種族・碑文など、画面に「発見」と出るもの） |
| `level_up` | レベルが上がった |
| `stairs` | 階を移った |
| `objective` | 遠征の目的を達成した |
| `extract` / `lifeline` | 帰還した／帰還の綱を使った |
| `guardian_down` / `warden_down` | 守護者／大守護者を倒した |
| `boon` | 加護を得た |
| `near_death` | HP が瀕死の帯に入った |
| `death` | 倒れた |

- `stairs` の音（`hollow` の `sound.json`）は、**仮の音**である（S9a。SEASON.md §57.3 の 3。2026-11-25）: 短い（鳴り終わりまで 0.5 秒以内）、下がる 3 音（度数 8 → 5 → 1）、ほかの合図より小さい `gain`（0.16）。音の担当が、後で差し替える。

## 3. 連動の枠: 何が何を動かしてよいか

音の担当は、§2 の入力だけを使って、次のものを動かせる。

| 動かせるもの | 中身 |
|---|---|
| パートの出入り | どのパートが鳴っているか |
| 音階 | 旋法・調（どの音の並びを使うか） |
| オクターブ・音域 | パートごとの高さ |
| 型（パターン） | パートが弾く音型の切り替え |
| 密度 | 音の数・リズムの細かさ |
| テンポ | 基準に対する倍率（0.75〜1.5 の間） |
| 音量・音色 | パートごとの大きさと音の作り |

**推奨の対応**（出発点。音の担当が変えてよい。変えたら音のテーマの説明に書く）:

| 入力 | 動かすもの | 考え方 |
|---|---|---|
| `scene` | パートの出入り・型 | 場面の骨組み。探索は少ないパート、戦いで打楽器と低音が入る、大守護者で全部 |
| `threat` | 密度 | 追う敵が増えるほど細かく |
| `hp` | オクターブ・音域 | 減るほど低く、または薄く |
| `depth_band` | 音階 | 深いほど暗い旋法へ |
| `depth_tier` | 基音・和声の並び | 同じ旋法のまま基音を移す、和声の並びを替える（地下 15 階より深い階にも変化を付ける） |
| `biome` | 音色 | 場所の質感 |
| `floor_kind` | パートの出入り | 聖域は静かに、大守護者の間は張りつめて |
| `telegraph` | 一時的な型の変化 | 構えの間だけ、保続音や休符 |
| `sense` | 特定のパートの音量 | 近づくほど前に出る |
| `stake` | 高いパートの出入り | 賭けている物が大きいほど、上に 1 声足す |
| `ailment`・`boost` | 音色の変化 | 濁り・明るさ |

**守ること**:

- すべての変化は、音の状態と、音楽の中の時間（小節・拍）だけで決まること。乱数で揺らすときは、小節の番号から決める（`Math.random` を使わない）。同じ状況で同じ音にするためである。
- 1 つの入力が変わっただけで、音楽の全部が変わらないこと（場面の切り替えを除く）。何が変わったかを聞き取れるようにする。

## 4. 時間の扱い

このゲームはターン制で、音楽は実時間で流れる。

| 項目 | 仕様 |
|---|---|
| テンポ | 実時間で一定。ゲームの手番の速さには合わせない |
| 状態の切り替え | 次の拍か小節の頭で行う（音のテーマが `quantize` で決める）。遅れは 2 秒以内 |
| 合図（キュー） | すぐ鳴らすか、次の拍で鳴らす（合図ごとにテーマが決める）。長さは 1.5 秒以内 |
| マクロの再生 | 1 回の呼び出しで何手番も進むとき、音の状態は画面の再生の位置に合わせて追う（最後の状態へ飛ばない） |
| 待ち時間 | 誰の番でもない間・AI の応答を待つ間は、今の状態のまま流し続ける |
| 同じ合図の連続 | 同じ合図が 0.15 秒以内に重なったら 1 つにまとめる |
| 場面の揺れ | `scene` が 1 秒より短い間に行って戻るときは、切り替えない |

## 5. 音のテーマ（定義ファイル）

音の担当の成果物。画像のテーマと同じ場所（クライアントのテーマ）に置く。

- **形式**: JSON の定義 1 つ（`sound.json`）と、任意の音の素材（OGG か WAV）。素材が無ければ、ブラウザの合成音（正弦波・矩形波・三角波・のこぎり波・ノイズ）だけで鳴らす。**素材なしで成り立つことを最小の要件とする。**
- **本物の MIDI ファイルは使わない。** 音は「音階の中の何番目の音か」（度数）で書く。音階を切り替えたときに、同じ型がそのまま新しい音階で鳴るようにするためである。

定義の中身:

| 項目 | 中身 |
|---|---|
| `tempo` | 基準のテンポ（BPM）と拍子 |
| `scales` | 名前を付けた音階（基音と、音の並び） |
| `parts` | パートの一覧。役割（低音・和音・旋律・打楽器など）、音の作り、基準のオクターブ |
| `patterns` | パートが弾く型。拍の位置・度数・長さ・強さの並び |
| `rules` | 「音の状態がこうなら、こうする」の並び。上から順に当て、後のものが上書きする |
| `cues` | 合図ごとの短い音 |
| `quantize` | 切り替えの単位（拍・小節） |

例（形を示すだけ。中身は音の担当が作る）:

```json
{
  "tempo": { "bpm": 84, "beats": 4 },
  "scales": {
    "shallow": { "root": "D3", "steps": [0, 2, 3, 5, 7, 9, 10] },
    "deep":    { "root": "D3", "steps": [0, 1, 3, 5, 7, 8, 10] }
  },
  "parts": [
    { "id": "bass", "role": "bass", "voice": { "wave": "triangle" }, "octave": 0 },
    { "id": "lead", "role": "lead", "voice": { "wave": "square" },   "octave": 2 }
  ],
  "patterns": {
    "bass_walk": [ { "at": 0, "degree": 1, "len": 1 }, { "at": 2, "degree": 5, "len": 1 } ]
  },
  "rules": [
    { "when": { "scene": "explore" }, "set": { "parts": ["bass"], "pattern": { "bass": "bass_walk" } } },
    { "when": { "depth_band": [2, 3] }, "set": { "scale": "deep" } },
    { "when": { "hp": "near_death" }, "set": { "octave": { "lead": -1 } } }
  ],
  "cues": {
    "crit_dealt": { "voice": { "wave": "square" }, "notes": [ { "degree": 8, "len": 0.25 } ] }
  },
  "quantize": "bar"
}
```

- 定義に知らない項目・知らない入力の名前があっても、クライアントは落ちずに無視する。
- 定義の細かい形（項目の名前、度数の書き方、音の作りの指定の幅）は、音の担当と実装担当が相談して決めてよい。変えてはならないのは §1〜§4 と §6 である。

## 6. 上限と、人間への配慮

| 項目 | 仕様 |
|---|---|
| 同時に鳴るパート | 6 まで |
| 同時に鳴る音 | 16 まで |
| 既定 | 無音。音を出すのは、利用者が画面で入にしたときだけ（ブラウザも、操作なしの再生を許さない） |
| 設定 | 入・切と音量。音楽と合図を別に切れる。設定は端末に覚える |
| 音量の跳ね | 場面や合図で、急に大きくしない。合図は音楽より少し大きい程度まで |
| 長く聞くこと | 探索の場面は、何十分も流れる前提で作る。同じ型だけを繰り返さない |
| 瀕死 | 警報のような、鳴り続ける不快な音にしない |

## 7. 置き場所と実装

| もの | 場所 |
|---|---|
| 音の状態を作る関数 | `packages/shared`（視界のデータと、届いた出来事から作る純粋な関数）。`client` は `engine` を import しない、の不変条件はそのまま |
| 鳴らす仕組み | `packages/client`（Web Audio）。画面（遊ぶ・観戦・リプレイ）が音の状態を渡す |
| 音のテーマ | クライアントのテーマの中。既定は「無音」 |
| サーバー・MCP・エンジン | 変えない |

**テスト**:

- 音の状態を作る関数は、引数がプレイヤーの視界のデータ（`PlayerView`）と届いた出来事だけであること（型で縛る）。World を受け取らない。
- 同じ入力から同じ音の状態になること。
- 視界の外の敵を足しても、音の状態が変わらないこと。

## 8. 最初に作る規模（目安）

- パート 4 つ（低音・和音・旋律・打楽器）。
- 音階 2〜3 つ。
- 場面 7 つのうち、`camp`・`explore`・`combat`・`warden` の 4 つを聞き分けられること。残りは近い場面と同じでよい。
- 合図は 7 つから（`hit_taken`・`crit_dealt`・`crit_taken`・`kill`・`level_up`・`objective`・`death`）。
- バイオームごとの音色は後回しでよい。

## 9. 入力を足したいとき

1. 音の担当が、足したい入力と、何に使いたいかを設計担当に伝える。
2. 設計担当が確かめるのは 1 点だけ: **その情報は、その人間の画面にすでに出ているか。**
   - 出ている → §2 に足す。
   - 出ていない → 足さない。先に「その情報をプレイヤーに渡すか」をゲームの設計として決める（渡すなら、AI にも人間にも同じ形で渡す）。
3. 足したら、本書を先に直してから実装する。

## 10. 実装担当の判断に委ねる点

- 音の状態を作る関数の、視界のデータの項目との対応（「追跡中」「構え」「守護者」を、どの項目から読むか）。
- 定義ファイルの細かい形と、読み込み・検査の作り。
- 合成音の作り（エンベロープ、フィルター、残響）の幅。
- マクロの再生の位置と音の状態の合わせ方。
- 設定の画面の置き場所。

## 11. 本書で決めていないこと（音の担当が決める）

- 調・旋法・旋律・和声・リズム・音色。
- §3 の推奨の対応を、どこまで採るか。
- 場面ごとの曲想と、切り替えのつなぎ方。
- 合図の音。
- 素材（録音した音）を使うかどうか。

## 12. 定義の形（版 1）と鳴らす仕組み（2026-11-18。実装担当が決めた。§5・§10 の取り決め）

鳴らす仕組みと、音の状態を作る関数を実装した。音の担当の仮の形（[SOUND_DIRECTION.md](SOUND_DIRECTION.md) §9・§17）を、そのまま**形の版 1** とした。試聴ページ（`docs/sound-audition/index.html`）の読み方と同じに鳴る。

| もの | 場所 |
|---|---|
| 音の状態を作る関数 | `packages/shared/src/sound.ts` の `soundStep(前の記憶, 視界, 届いた出来事, カタログ)` |
| 定義の読み方（検査・規則の当て方・度数） | `packages/client/src/sound/def.ts` |
| 同時に鳴る音の間引き | `packages/client/src/sound/voices.ts` |
| 鳴らす仕組み（Web Audio） | `packages/client/src/sound/engine.ts` |
| 進行役（設定・テーマの読み込み・場面の揺れ・合図のまとめ） | `packages/client/src/sound/director.ts` |
| 設定の画面 | `packages/client/src/ui/sound.tsx`（遊ぶ・観戦・リプレイの上の帯の「音」） |

### 12.1 テーマの登録

- `themes/index.json` の項目に `kinds` を持たせる。`["sound"]` は `sound.json` を持つ音のテーマ、`["image"]` か `kinds` 無しは `theme.json` を持つ画像のテーマ。両方持つなら `["image", "sound"]`。
- 画像のテーマの選択には画像のテーマだけ、「音」の選択には音のテーマだけが出る。`hollow` を `["sound"]` で登録した。

### 12.2 形の版 1（§9・§17 の形。細部の解釈）

- `formatVersion` は 0（仮の形）と 1 を同じに読む。新しく書くなら 1。それ以外の版は読まない（無音のまま、画面に読めない理由が出る）。
- 知らない項目は無視する。7 つ目からのパートは捨てる（ブラウザのコンソールに書く）。読めない音階・型・合図も捨てる。
- 音名は `A`〜`G`、`#` か `b`、オクターブの数（例 `D3`・`Bb2`・`C#3`）。
- 型の `at` は 16 分の格子に丸める。型は**通しの位置**から読む（切り替えても頭からやり直さない）。`only` の「回数」は、通しの位置 ÷ 型の長さ（切り捨て）。
- 度数は 1 始まり。8 以上は上のオクターブ、0 以下は下のオクターブ。和音（配列）は 1 音の大きさを 1/√音数 にする。
- `rules[].when`: 値は 1 つの値・値の並び（どれか）・`{ min, max, mod, rem }`（数の入力だけ。どれも省ける）。項目は「かつ」。**知らない入力を条件に持つ規則は当てない**（新しい入力を使うテーマを古い画面で鳴らしても、誤って当たらない）。`depth_band` も使える。
- `rules[].set`: `scale`・`tempo`（倍率。0.75〜1.5 に収める）と、`parts.<id>` の `on`・`pattern`・`density`・`octave`・`gain`・`voice`。上から当て、書いた項目だけを上書きする（`voice` も項目ごと）。パートの既定は 切・密度 2・オクターブ 0・音量 1。
- `voice`: `wave`（sine・square・triangle・sawtooth。打楽器だけ noise）、`attack`・`decay`・`sustain`・`release`（秒）、`lowpass`・`highpass`（Hz）。打楽器の音（`parts[].kit`）は `wave`・`freq`・`attack`・`decay`・`lowpass`・`highpass`。
- `cues.<名前>`: `start` は `now` か `beat`（次の拍の頭）。`at`・`len` は秒。1.5 秒より後に始まる音は捨て、1.5 秒を超える長さは切る。`gain` の既定は 0.4。`hit` は `kit` を持つパートの打楽器の音。度数はそのときの音階。
- `quantize` は `beat` か `bar`。`fade` はパートの出入りの秒（既定 0.3）。

### 12.3 鳴らす仕組み

- **既定は無音。** 上の帯の「音」でテーマを選んだ操作の中で鳴らし始める。前に選んでいたなら、ページを開いただけでは鳴らさず、最初のクリックかキーで鳴らし始める。音量、音楽・合図を別に切れる。設定はその端末に覚える（`localStorage` の `muse.pref.sound`）。
- 音楽は 50 ミリ秒ごとに 0.2 秒先まで予約する。音の状態の切り替えは `quantize` の頭で行う。
- **同時に鳴る音は 16 まで**（音楽と合図を合わせて。打楽器の 1 打も 1 音と数える）。新しい音を置くとき、その音が鳴る間のどの時点でも 16 を超えるなら、ほかの音を早めに止める（6 ミリ秒で消す）。止める順は、余韻に入った音楽 → 古い音楽 → 余韻に入った合図 → 古い合図。場面を切り替えた直後の余韻の重なり（SOUND_DIRECTION.md §12）は、これで切られる。パートは 6 まで。
- **場面の揺れ**: `scene` は、新しい場面が 1 秒続いてから切り替える（1 秒より短く行って戻るときは切り替えない）。ほかの入力はすぐ渡す。切り替えの遅れは、多くて 1 秒 ＋ 次の拍（96 BPM・×0.75 でも 1.9 秒）。
- **合図**: 同じ合図が 0.15 秒以内に重なったら 1 つにする。画面を開いた最初の視界（それまでの出来事がまとめて届く）、リプレイで飛んだとき、×8 より速い再生では鳴らさない。
- **マクロ**: 遊ぶ画面には 1 歩ごとに視界が届くので、そのたびに音の状態を作る（画面の再生の位置を追う。最後の状態へ飛ばない）。
- **観戦・リプレイ**: 選んでいるプレイヤー（俯瞰でも、追う相手の選択。リプレイで選んでいなければ最初のプレイヤー）の視界（`projectPlayerView`）と、その人に届く出来事（`filterEventsForPlayer`）から作る。観戦者だけに見える情報は使わない。
- **観戦の再生の列**（S13。DESIGN.md §2.1）: 観戦では、合図と音の状態は、歩が届いたときではなく、その歩を描いたときに作る。今の所へ飛んだとき（おくれが 30 秒を超えた・「今の所へ」・タブを表に戻したとき）は、途中の合図を鳴らさず、最後の視界で音の状態だけ合わせる。

### 12.4 音の状態の読み方（§10 の判断）

| 入力 | 読むもの |
|---|---|
| 「見えている」 | 視界の `entities`（いま見えている者。覚えているだけの者は入らない） |
| 追跡中 | `awareness` が hunting で、逃げていない（`fleeing` でない）モンスター |
| `scene` の `warden`・`guardian` | 見えているモンスターの `guardian`（`warden` の印があれば大守護者） |
| `scene` の `combat` | 追跡中の敵が隣にいる。または、自分の手番数で直前の 3 手番のうちに、自分が攻撃した（外れも、投げた物も）か攻撃された（見えない相手からも） |
| `scene` の `ended` | 視界の状態が ended か dead、またはランが終わった。階の値は最後にいた階のまま |
| `telegraph` | 見えているモンスターの `intent`（予備動作） |
| `sense` | 視界の気配の遠近（観測の気配の文と同じもの） |
| `floor_kind` | 階の種類の ID が `core:standard`・`core:sanctuary`・`core:warden_hall` ならその名前。大空洞・宝物庫階などは `other` |
| `stake` | 持ち帰っていない戦利品（観測の戦利品と同じ数え方）。「遠征 1 回の確定の最高」は、届いた遠征の終わりの出来事から覚える。まだ覚えていない（ページを開き直した）ときは、確定点が 0 なら最高 0、そうでなければ 1 までにとどめる |
| `ailment`・`boost` | 自分の状態異常の `tone`（`statuses.json` に足した。bad: 毒・減速・睡眠・朦朧・怯え・錆、good: 加速・身かわし・構え。帰還中はどちらでもない） |

| 合図 | 届いた出来事 |
|---|---|
| `hit_dealt`・`crit_dealt`・`miss` | 自分の `attack`（当たった・会心・外れ）。攻撃の出来事の無い投げた物の命中は `hit_dealt`、外れは `miss` |
| `hit_taken`・`crit_taken` | 自分が的の `attack`（当たった・会心）。攻撃の出来事の無い被害（罠など）は `hit_taken`。毒の刻みでは鳴らさない |
| `kill` | `died` で倒したのが自分 |
| `guardian_down`・`warden_down` | 見えていた守護者・大守護者の `died`、または `warden_slain`。自分が倒したなら `kill` と両方起きる（テーマが選ぶ） |
| `telegraph_start` | 見えている敵に、前の視界に無かった構えが出た |
| `pickup`・`treasure` | 自分の `item_picked_up`（宝の分類なら treasure） |
| `discovery` | `haul_changed` で発見の点が増えた（画面の「発見 +50」） |
| `level_up`・`boon` | 自分の `level_up`・`boon_granted` |
| `stairs` | 自分の `entity_changed_floor` |
| `objective` | `objective_completed` |
| `extract`・`lifeline` | 自分の `player_state`（キャンプへ。理由が extracted・withdrew か lifeline） |
| `near_death` | 体力の帯が瀕死に入った（前の視界では瀕死でなかった） |
| `death` | 自分の `died`、または `player_state` の dead |

### 12.5 確かめたこと

- `packages/tools/test/sound.test.ts`（7 件）: 同じ入力から同じ状態、視界の外の敵では変わらない、World を渡すと型で弾かれる、場面の決め方、脅威の段、深さ、気配、構え、状態異常、瀕死、終わり、合図の出来事との対応。
- `packages/client/test/sound.test.ts`（6 件）: hollow の `sound.json` を警告なく読む、規則の当て方（項目ごとの上書き・`depth_tier` の余り・バイオームの音色・知らない入力・テンポの幅）、度数、型の位置、間引きの順。偽物の AudioContext で hollow を 110 秒鳴らし、11 の場面を 10 秒ごとに切り替え、その直後に合図 7 つを重ねても、同時に鳴る音が 16 を超えないこと（間引きを外すと 21 になる）。
- 実際の画面（ブラウザ）: 遊ぶ画面で hollow を選ぶと鳴り始め、戦いの型（低音・和音・打楽器、テンポ ×1.3）になる。手番を進めると、記録の行と同じ順に `miss`・`hit_taken` が出て、体力の帯と脅威が変わる。観戦画面でも、追う相手の視界から同じ状態になる。**耳での確認はしていない**（実装担当は音を聞けない）。
