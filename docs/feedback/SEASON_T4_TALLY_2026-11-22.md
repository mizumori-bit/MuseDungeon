## 8. 数え方・数えられなかったもの

### 数え方

- 数え上げは t3 の集計のスクリプトの読み込み部分（`load.cjs`・`lib.cjs`）を写し、1〜7 は t4 用に新しく書いた（置き場: セッションの作業ディレクトリ `tally_t4`）。`E:\MuseDungeon-trial\trial-runs\t4\` は読むだけで、書いていない。
- 手番 = `turn_began` のうち、その参加者の `actor`（戦士の ID）のもの。予算 = その累計（`participants.json` の `turns` と一致）。遠征の範囲 = `expedition_started`〜`expedition_ended` の `seq`。命令の遠征への割り当て = 命令の `resultSeq[0]`（マクロの親は最初の子の値）。「何手番目」= その出来事の `seq` までの手番の数。
- 最終の順位 = `participants.json`・`supplies.json`・`public.json`・`spots.json` から、サーバーの順位の規則（値の大きい順、同着は使った予算の少ない順。冒険賞の同着は到達時の予算、貢献賞の同着は最後の first の予算）で数え直した。支援賞の値は `supplies.json` の `takenBy`（先に着いた 1 人の取り。二重は数えない）。最後の `season_sync` の賞の表示（参加者が見たもの）と一致した（1 の参考の行）。
- 1 の「報告した階段・特別な場所の延べ数」は `stairs_reported` の `stairs`・`spots`。「最初に報告した数」は `participants.json` の `firstReports`。
- 4: 預けた品 = `supply_deposited`（`n` は預けた者の通し番号。`supplies.json` の `n` と対応させて id を付けた）。取った品 = `supply_taken`（取った者の run の出来事）。「数えられたか」は `log.jsonl` の `supply_taken`（`counted: true`）と `supply_double`。取った後の使用 = その後の `item_used`・`item_thrown`（本人・同じ種類）。**同じ種類の持ち物は 1 つの束になるので、取った品そのものの使用かどうかは区別していない**。`thought` は、その使用の命令（マクロの子は親の `thought`）。4.6 の語は 4.6 の本文。
- 5: 基礎点は `expedition_started` の `points`、確定点は `payout.banked`。守護者（格・名・型・種族・体力・装甲）は、その遠征を始めたときの提示（直前の `expedition_offered` の、選んだ `offer` 番号の `guardian`）から。与えた被害・受けた被害は `damaged`（守護者の ID は `entity_spawned`・`guardian_state` の `core:guardian` 付きから集めた）。5.1 の「同じ」= 名前が同じ。
- 6: 大守護者の ID は `entity_spawned` の `core:cave_troll`（`core:guardian` 付き・地下 5 階）。被害の内訳は `damaged` の `via`。Lv・最大 HP・装甲は遠征の開始直前の `player_state`・HP の再構成。使った品 = `item_used`・`item_thrown`・`ability_used`。受けた被害 = プレイヤーへの `damaged` の合計。
- 3: `thought` は語の機械的な拾い出しだけ（正規表現は 3.0）。手で読んだ分類（理由・迷う・言葉だけ）はしていない。
- 7.2: t3 の 7 と同じ近似（`fight` の子の命令の結果範囲・HP の再構成）。t3 の値は前回の集計から写した。

### 数えられなかったもの

- **断られた命令**（`bad_request` ほかのエラー応答）の数。`commands.jsonl` にはゲームに届いた命令だけが残る。そのため、**「1 回の遠征で 1 つまで」の上限に当たって断られた回数**、**置き場がいっぱい（5 個）で断られた回数**、預けられない品（装備・遺物など）を預けようとして断られた回数は、記録から分からない。`take_supply` の命令 6 件・`deposit_supply` の命令 10 件はすべて成功しており、`supply_taken` 6 件・`supply_deposited` 10 件の出来事と一致する。
- **「通る目安」**（大守護者の候補に添えられる、守護者に通るかの目安）の表示そのもの。記録された提示（`expedition_offered`）には載っておらず、観測の応答にだけ載る。参加者がこれに触れた `thought` は、6.3 の語（通る目安・見込み・挑む・大守護者など）で拾った範囲だけ。
- マクロの停止理由（`hp_floor`・`hp_risk` など）そのもの。7.2 の A・B・D は近似。
- 参加者が見た画面（キャンプの賞の表示・置き場の「できること」・「あなたの預けた品を○○が取った」の知らせの文面・規則の文）。観測の応答は記録されていない。最後の `season_sync` の賞の値だけは記録にある（1 の参考の行）。
- 取った品そのものの使用（束の区別）と、取った品が使われなかった理由の自由記述。取った品の効果（例: 回復の薬を飲んで生き延びたか）は、被害・HP の経過と合わせて読んでいない。
- 4 の「預けるためだけの遠征」は機械的な目安（遠征全体 10 手番以内）。預けた遠征の目的・手番は 4.2 の表で読める。
- 5 の守護者の被害の合計が、守護者の体力に合わない遠征がある（体力は遠征ごとに別の守護者で、提示の幅 `hpRange` の中。倒さなかった遠征は合計が体力に満たない）。大守護者は、倒したハギ E11 の被害の合計が体力と同じ 90 で、ほかの遠征（倒していない）は 90 に満たない。
- 5 の「基礎点が 528 から 2112 に戻る」理由（サーバーの規則）は調べていない。5.1 の列は、前の遠征の与えた被害・手番・終わり方・守護者の名と、次の遠征の基礎点・確定点・守護者の名を並べただけ。
- サーバーの再起動の有無・記録の欠けは確かめていない（`seq` の連続性は見ていない）。
- 特別な場所を見たのに報告しなかったもの。道しるべの道（地図に載ったマス）の長さ・使われ方。公開された階段を使ったかどうか（3.3 の「道しるべ」の語を含む `thought` だけ）。
- 野営の火は置かれなかったので、火の使われ方（t3 の 6）は数えていない。
