## 3. `thought` の数え上げ

### 3.0 数え方

- 対象: `commands.jsonl` の `source: "mcp"`（参加者が呼んだ命令）。マクロの子（`source: "macro"`）は同じ `thought` の写しなので数えない。`season_sync`（報告の命令の記録）は `source: mcp`。`choose_perk`・`choose_boon` には `thought` が無い。
- 場面（1 命令に 1 つ。上から順に当てる）: (a) `start_expedition`／(b) `extract`、`use` の帰還の綱、および `thought` に 帰還・撤退・帰る・帰って・引き返・綱・退く・退い を含む命令（階段へ戻る移動・「危なければ綱で帰る」の条件文を含む）／(c) 報告（`season_sync` の reason `report`）／(d) `choose_perk`・`choose_boon`／(e) そのほか（`place_fire` は (e)）。t0 と同じ分け方。
- 理由の種類（手で読んで分類。1 つの `thought` が複数に入ることがある）: 冒険賞（最深）、貢献賞（報告・公開）、生還賞（倒れない・確定点・首位）、順位・他の参加者の名前、行動予算（手番の節約・残り予算・同着の決まり）、**支援賞・野営の火（t1 で足した）**。
- 区分: 理由（R）= その言葉が、その命令を選ぶ根拠として書かれている。迷う（U）= 語はあるが根拠かどうか、または何の賞か分からない。言葉だけ（W）= 状況の説明にとどまる（理由の語が無い報告の命令を含む）。
- 行動予算（BUD）は、「予算 N」「残り N 手」など残りの手番を示して選択の前提にしたもの、「予算が少ない／余裕がある」と書いたもの、「手番を節約する」と書いたものを R に入れた。残りの数を書いただけで、選択と結びつけていないもの（3 件）は W。
- 別枠で数えたもの（6 種には入れていない）: 回の区切り（SEG）= 「呼び出しの区切り」「今回の呼び出しの残りでは」など、1 回の遊び（呼び出し 120 回ほど）の区切りを理由にしたもの。公開階段の利用（PUB）= 公開された階段を理由にしたもの。開始位置（START）= 「次の遠征をその階段から始めるため」。

### 7.1 `fight` の止まり方（`hp_floor`・最悪の被害）

**止まった理由は、記録に残らない**（マクロの停止理由 `stop`〔`hp_floor`・`hp_risk` など〕は MCP の応答にだけ載り、`commands.jsonl`・`events.jsonl` に無い。t0 の `no_progress` と同じ）。断られた `fight`（始める前に `hp_floor` で断られたもの）も `commands.jsonl` に残らない。そこで、記録から次の 4 つの近似で数えた。

1. **A: 終わったときの HP が床以下**（`hp ≤ hpFloor`。マクロは「HP が hp_floor 以下」で止まる規則なので、`hp_floor` で止まった確かな数。`hpFloor` を渡していないときの床は最大 HP の 50%）。

3. **C: `thought` に「床を下げる」「hp_floor を下げる」と書いたもの**。
4. **D: 1 手番以内で終わった `fight`**（`hp_risk`・予備動作・新しい敵などで早く止まったものを含む。上限に近い）。

## 11. 数え方・数えられなかったもの

### 数え方

- 手番 = `turn_began` のうち、その参加者の `actor`（戦士の ID）のもの。予算 = その累計（`season_sync` の `budget.at` と一致）。
- 遠征の範囲 = `expedition_started`〜`expedition_ended` の `seq`。命令の遠征への割り当て = 命令の `resultSeq[0]`（マクロの親は最初の子の値。キャンプ中の命令は遠征 0 扱い）。
- 最終の順位 = `participants.json`・`fires.json` から、サーバーの `computeStandings`（`packages/server/src/season/SeasonService.ts`。読み取りだけ）と同じ規則で数え直した。
- `thought` の場面分けと理由の分類は、t0（3.0）と同じ。手で読んで分類した（分類の元は 3.7（理由 R 全件）・3.5（U）・3.6（W））。依頼の種類に入らない語（点・経験値・体力・装甲だけの理由）は数えていない。語の出現の表（3.3）だけは機械的に文字列を数えた。
- 「ある賞のために別の賞を捨てた」(3.8) は、原文に賞・順位・予算・火の語があり、記録で見送った数字が確かめられるものだけ。(a) の選ぶ命令は、提示（`expedition_offered`）の点と、選んだ枠（`start_expedition.offer`）を比べた。
- 4 の HP は、`damaged`・`healed` の `hpAfter` と `stats_changed`・`put` の `stats` から作り直した（最後に出たものを採る）。火との距離は、プレイヤーの `entity_moved` の位置と火のマスのチェビシェフ距離。近くの敵は、`entity_spawned`・`entity_moved`・`ai_state_changed` から作り直した位置と状態（記録の中の世界の状態。参加者に見えていたかどうかではない）。
- 4.4 の順位の表示は `season_synced.seasonAfter.awards`（遠征の終わりごとに記録）。
- 5 の「着く」「降りた」は t0 と同じ。5.3 の `explore` の手番は、マクロの子の `turn_began`（参加者）の数。
- 6 の「挑んだ」は目的が大守護者の遠征。目的が別の遠征で守護者に会った場合は含めていない。
- 7.1 の `fight` の止まり方は、記録に停止理由が無いので近似（A・B・C・D の定義は 7.1）。

### 数えられなかったもの

- `fight` などマクロの停止理由（`hp_floor`・`hp_risk`・`no_progress` など）そのもの。MCP の応答にだけ載り、記録に無い。始める前に `hp_floor` で断られた `fight` の数も。
